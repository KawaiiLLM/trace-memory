# Trace Memory — domain glossary

Terms only. No implementation detail. When a term here conflicts with usage in code or prompts, this file wins and the other side is fixed.

## Layers

- **Raw** — the conversation as the host recorded it: user messages, tool calls with results, assistant text. The only source of truth. Never edited.
- **Source entry** — one completed native conversation message: user text, assistant content with tool calls, or a tool result. Identity is its native id within the session lineage, never its text. It belongs to a Turn and receives an immutable Turn-local E ordinal; branch gaps never renumber it. The host normalizes ordered content blocks once for rendering and exact citation validation. Plugin injections and summaries are never sources.
- **Compressed Raw view** — the shared, bounded head/tail excerpt of one source entry, in Pi's compaction line shape with stable entry/block addresses (`[T<n>#E<m>@text] user: …`, `[T<n>#E<m>@<callId>] <tool>(<key>=<JSON>)`, `[T<n>#E<r>@<callId>] <tool> <status>: …`) and honest omission counts in one marker family (`[... N characters truncated]`). One view everywhere, under one profile of three independent budgets: `E` for the whole entry, `C` for each tool-call part, `R` for each tool-result part, each including the labels, syntax and markers inside it. A marked compressed view is visible Raw whether or not it was truncated. The original Raw remains available through full trace, uncompressed under the same labels, with lossless cursor pagination (default 2,000 estimated tokens per page).
- **Turn** — one user message and everything it triggered until the next user message. A compaction is also recorded as a turn, with no facts.
- **Fact** — a source-grounded episode of a Turn. New facts carry text and one or more exact entry sources; core derives a `role` (user, assistant, observation) for each source, with the original Pi agent or Claude Code harness shown for assistant entries. Optional support/negate relations annotate facts but are not required. Legacy category, actor, status and quote remain readable unchanged. Noter-written fact text is limited to 1,000 estimated tokens; manual writes commit immediately.
- **Fact group** — the display of selected facts under their owning Turn: Turns in chronological start-time order, facts in ascending F-id order. A group need not cover its entire Turn; grouping changes neither citation scope nor processing membership, and all original source references stay on each fact.
- **Knowledge** — one durable, decontextualized conclusion grounded in facts. New writes use five categories: constraint, understanding, goal, open, reference. Legacy mechanism/term group under understanding and dispute under open without rewriting stored revisions. Each immutable revision stores the complete resulting body (or archival state) and exact lineage. Consolidator- and Dreamer-written text is limited to 1,000 estimated tokens per result, including each split child; manual writes are unchanged.
- **Supports** — the facts directly grounding one revision. A revision applies when its own scope admits the reader and every direct support belongs to the revision's scope and to its fact owner's current foreground. Lineage is provenance, not a recursive applicability condition. Evidence-driven changes store exactly their submitted supports. When a trusted Dreamer submits an empty list, core materializes the exact parents' supports at commit: one parent's set for update/archive/split and the union of both sets for merge. Migration fills historical empty sets in parent-before-child order; a revision stays empty only when its entire ancestry is empty.
- **Knowledge version address** — bare `K12` selects current; `K12#qfzt` matches an exact immutable version and is required for mutation bases. Per-identity `K12@v3` ordinals include all branches and never renumber with scope. Complete model bodies carry tags, continued bodies only after their final fragment; previews, notices, diffs and body-free receipts carry no tag. Reads hold no grant ledger. Human audit, database keys and actual-delivery carriers retain global commits.
- **Knowledge lineage** — immutable revision history: creation has no parent; update/archive have one; merge has exactly two distinct-identity parents and one result, with the older Knowledge identity as survivor; split has one parent and atomically creates exactly two new Knowledge identities. Effective resolution is stateless: among branches whose revisions' direct facts currently apply, the later committed conflicting branch has priority; an earlier branch returns when the later branch stops applying. The same resolved graph supplies reads and atomic stale-base write checks, so consumers never expose an effective fork. Archives participate before body filtering. Parent and merge/split links preserve provenance without inheriting applicability.
- **Trigger origin** — the target memory-session identity plus one triggering `source_entries.id`, frozen for execution and run audit. An explicit trigger is used when supplied; otherwise choose the last entry on the target ancestry. Later foreground navigation does not move it; historical absence stays unknown. Existing stored multi-id origins remain unchanged and their final id is the trigger. Origin is provenance, not knowledge validity or permission to write a stale base.
- **Reason** — the commit message of one knowledge commit: what changed and why it was chosen. It is not a durable claim and has no authority of its own; it establishes no evidence, scope, applicability, accounting coverage or completion level, and addresses written in it are never read as citations.
- **Topic** — a subject label on one knowledge revision: the module, component or domain the conclusion is about, beside its category. Labels are free strings, trimmed, deduplicated and versioned with the revision that carries them; several may apply and none is required. Classification only — a topic changes no scope, evidence permission, lifecycle or eligibility, and sharing one merges no knowledge.
- **Noting** — the phase in which the Noter turns raw into facts. Each eligible entry completion checks for 10,000 pending compressed-view tokens; a run processes the oldest whole-entry prefix within 10,000 tokens and the model context capacity. A partly processed Turn may still have pending entries.
- **Dreaming** — bounded fresh-subagent update/binary-merge/binary-split/archive maintenance of one due Knowledge pool. Every live ingested entry checks each applicable pool independently (new selected history in CC bootstrap checks the complete final path once; restart/restore with no appended entries grants no opportunity): current visible versions without a processing record in that pool are pending once, archives included (still excluded from pool size): an update weighs the amount of change since the version last confirmed in this pool, an archive weighs the removed body, and either without a confirmed baseline here counts at its full rendered size. A pool with nonempty pending versions is due when their weight reaches the smaller of the configured Dreamer cap and its own budget (global/project/session: 4k/5k/1k by default); its frozen range takes an oldest-first prefix under the pool's soft batch budget, always admitting the first item even when its framing exceeds that budget. The model input capacity remains a hard limit. A configurable wall-clock bound (ten minutes by default) replaces the tool-round ceiling on both hosts. Current reference knowledge and the range share the Knowledge window plus shared allowance; direct facts have a separate 10k cap. Exact version tags, current visible bases, pool authority and the live claim fence guard immediate atomic writes. A tag matches a version, not a read history. Reasoned skips use untagged exact history addresses and need no full-body reread; they confer no mutation authority. Processing records only skipped frozen versions and own revisions, including on failure or cancellation; untouched material stays pending. Ranges end once, and own outputs do not trigger themselves. Partial writes survive later failure.
- **Consolidation** — the phase in which the Consolidator creates, updates and archives knowledge from facts; merge and split remain the Dreamer's. Its first valid submission commits without a review round. A claim that continues an existing item updates or archives that item at the exact version the Consolidator read; only a claim with no continuing item creates one. Each eligible entry checks for 5,000 rendered tokens of applicable unconsolidated facts and takes an oldest-first whole-fact prefix within 10,000 tokens. Manual knowledge writes allow fact-backed create and archive only. Outside explicit manual catchup, worker completion starts no phase; shutdown and tree switching never do.

## Relations (annotations, never derived state)

- **Support** — a newer fact affirms an older one: adoption, approval, agreement, an answer, a restatement, execution of a ruling.
- **Negate** — a newer fact opposes or invalidates an older one: withdrawal, veto, found wrong, a new state overturning the old, doubt, objection, evidence that does not fit.
- **Strength** — the Noter's confidence that the relation holds: *strong* when the raw states it, *weak* when inferred or partial. Who acted is carried by the fact's category and actor, not by the strength.
- No fact is ever hidden or retired by a relation. Automatic and path-scoped collection material shows a relation only when both Fact endpoints are on the selected path. An explicit `F<n>` trace remains unrestricted and marks relations whose other endpoint is inapplicable there. Relations show the Consolidator the shape; the Consolidator judges.
- **Dispute** — the Consolidator's judgment that two accounts of the same object under the same conditions coexist without a ruling. A category of knowledge, not a relation.

## Scope and attribution

- **Enrollment** — the durable enabled or disabled participation of one memory-session identity, changed by `/trace on` and `/trace off` (in Pi) for that identity alone, immediately and without a reload. Explicit intent overrides its derived default; shared forks and clones share the switch. Disable pauses future work and injection while retaining memory and unrestricted reads. There is no global participation switch.
- **Baseline** — the installation-scoped instant of the plugin's first successful initialization, retained across restarts and upgrades. Only native sessions created strictly after it default enabled; unknown or malformed creation times default disabled.
- **Session** — one host conversation. Gets an id only once an assistant reply exists.
- **Lineage cursor** — one native foreground within a memory session, persisted as `(session, lineage) → (branch, head)`. Each lineage moves independently and retains its cursor while closed; reopening adopts the same key. A session with no cursor treats all stored paths as active, while any recorded cursor makes only the recorded lineages' paths active. Fact liveness requires one complete cursor path to contain its Turn, source Turns and bound entries; membership is never assembled across sibling paths.
- **Executor** — an enabled active host runtime with one slot per phase. Noting and Consolidation can overlap and prefer their own eligible work before borrowing a closed tail. Dreaming shares one database-wide seat and processes a due pool visible at the executor's node, never a borrowed closed-session task.
- **Closed-session scope** — the Noting/Consolidation borrowing policy: off leaves tails pending, project allows the same project (default), and global allows any project. Borrowing selects only retained active lineage cursor paths (including ancestors up to each exact head); abandoned siblings stay pending until reactivated. A session without cursors retains all-path compatibility, while an invalid cursor fails the borrowed scan. The executor must be enabled and open. This policy does not change current-session work, manual catchup or Dreaming.
- **Target** — the memory session and branch whose evidence a worker processes. Its project, costs, commits, progress and deliveries remain its own even when another executor hosts the worker.
- **Claim** — exclusive ownership of one target's phase across branches and executors, identified by an executor, a token and a thirty-minute expiry. Current ownership fences commits; reopening immediately replaces another executor's token. An unexpired Dreaming claim also occupies the database's sole Dreamer seat. Cancellation closes knowledge tools immediately but retains the exact claim through terminal processing; disabling the executor may not prevent that bookkeeping. Token, expiry, takeover, project and frozen-range checks remain required.
- **Closed** — a session marked by normal shutdown and cleared on restore. For CC, a non-clear native SessionEnd closes its bound lineage without requiring executor termination or complete tail import; the core session stays open while another lineage is live. A stale native process cannot close a reopened session. MCP executor shutdown alone, a crash or an expired claim does not establish closure.
- **Project** — the unit that shares knowledge. Shared membership comes from an explicit user command (`/trace project <name>` in Pi, `trace project <name>` in CC) or, for a new session, from its directory: the session records its repository root (the parent of git's common dir, so worktrees share it) or the real path of cwd, and joins the project that directory's recorded sessions already belong to when that is exactly one (62); none or several keep the session's own project; the home and temporary directories never key; sessions from before 62 record no directory and count for nothing; an explicit command always wins. The same name in the same database identifies the same project. Changing project ownership requires the declaring session to have no running N/C/D and no reached N/C/D trigger, including all applicable knowledge pools. Refusal starts no work and queues no declaration. Other sessions do not block the move; their in-flight writes still face ordinary authority checks. Moved-in project revisions become pending again in the destination, including on a return move, by clearing only their destination processing records in the relabel transaction. Order follows revision creation, not move time. Unrelated destination records and global/session processing records stay unchanged.
- **Scope** of a knowledge item — `session` (holds only in that session), `project`, or `global` (about the user, the environment, general working method).
- **Knowledge budget policy** — one transactional database row with Global/Project/Session pool budgets, defaulting to 4k/15k/1k. Pools measure current visible non-archived versions, regardless of processing records. Their safe-integer sum supplies the 20k Knowledge base window; Dreamer's effective pending trigger is the smaller of its configured cap and the pool budget. A budget caps a Dreamer run and its effective pending trigger, not writes; exceeding it alone does not start a run. Settings edits the database, not Pi files. Migration upgrades an unchanged old-default 4k/10k/1k row; any other stored policy is retained and reported.
- **Manual catchup** — `/trace catchup`'s finite, explicit Noting drain of the current enabled session's selected branch: bounded subagent batches below the normal Noting trigger, within a frozen entry-id boundary. At start and after each successful catchup-owned N, C or D completion, one checkpoint checks all three phases: N drains its frozen boundary, while C and D use ordinary due rules. Noting and Consolidation can overlap, with one seat each per session; Dreaming has one database-wide seat. A busy trigger is discarded, not queued or replayed on release. Completion requires an exhausted frozen Raw backlog, no due C or D, and no owned work still running. Below-threshold facts and knowledge need not be empty. Empty or dropped results do not re-arm the loop. A failed catchup step immediately retries the same phase under its existing boundary, without checking other phases; ordinary logical-task failure accounting turns memory off after three consecutive failures and ends the drain. Successful completion checks all three phases. Cancellation ends the drain. Stop/off/shutdown/path changes fence further launches. This is the sole completion-chaining exception; later Raw never extends its frozen boundary.
- **Stop** — `/trace stop`'s cancellation of one executor's background work (its own manual catchup plus any ordinary or borrowed work), reusing the same claim, token-fence and cancellation machinery as shutdown. It never disables enrollment, never edits configuration and never touches another executor's claim.

## Reading

- **Foreground Knowledge delivery** — before every enabled ordinary prompt, the host may publish one Knowledge-only hidden message. The core selects applicable current exact revisions not already visible at that version, suppresses only changes whose nonempty direct supports are all visible as Facts or are all proven to bind to retained original/bounded Raw entries, and emits applicable archive/supersede/merge/split notices separately from bodies. The Knowledge base plus the configured shared allowance (`compaction.sharedAllowanceTokens`, 10k by default) charges retained applicable Knowledge bodies and state notices first; candidates then fit as whole rendered items. No Fact, Raw, omission-only, initial-only, command-generation, or processed-status material is published.
- **Injection** — the same Knowledge renderer and evidence-aware foreground predicate, used by every ordinary prompt; compaction separately carries knowledge, recent facts, and pending compressed Raw views. Knowledge is one oldest-first list, each item retaining its category label. A common header explains that later claims on the same object stand until merged; budget selection drops the oldest optional items first. Within one CC 24-segment render, knowledge is packed oldest-first with next-fit, never backfilling earlier segments; recency is the existing segment number followed by position within the segment, not native arrival order. Facts and Raw may fill gaps. Every capacity check prices the same final single-list carrier that is emitted.
- **Compaction** — replacement of the context with the injection block. Over a frozen snapshot of the path it has one outcome: a custom replacement that fits its windows, truncating unprocessed material rather than delegating (73). The core allocator calls no model and never asks for the host's native compaction for capacity; only an unexpected host-caught error leaves native compaction to the host. Truncated unprocessed material stays pending, and the host warns the user in the foreground.
- **Material window** — a compaction part: Knowledge has a database-derived 20k base and facts/Raw have configurable 10k bases (`compaction.factsTokens`, `compaction.rawTokens`). The shared allowance is one configured value (`compaction.sharedAllowanceTokens`, 10k by default), not derived from the triggers. Knowledge fills its base and borrows the allowance first; then Raw takes the newest contiguous span, pending entries borrowing what Knowledge left and already-noted entries only the Raw base; then facts take the newest not wholly covered by that span, unconsolidated facts borrowing what Raw left and consolidated facts only the facts base. Each window is charged exactly what it emits, its receipts and framing included; a window with no room even for its receipt emits nothing. Bases never lend to one another. Knowledge bodies are optional current-version material. Consolidator and Dreamer Knowledge can use base plus shared allowance.
- **Refill** — superseded by the single allocation under Material window (73): already-processed Raw and facts fill only their own base remainder, after the unprocessed material they sit beside. A fact is excluded only when its nonempty complete source-entry binding is fully covered by the final Raw span or retained originals/recognized bounded carriers; this applies to unconsolidated facts too, which stay pending in the store. Unknown, incomplete or partly uncovered bindings stay eligible. A discarded summary proves no retained coverage. Omitted items start no work, reset no processing and claim no supplied IDs.
- **Memory material coverage invariant** — withdrawn by 73: a compaction may truncate unprocessed Raw and unconsolidated facts, newest kept and oldest omitted with a receipt; the omitted material stays pending in the store for Noting and Consolidation, and the user is warned. An ID or omission receipt is not a body, and bounded Raw is not semantic losslessness.
- **Compaction boundary** — the last compaction the host successfully persisted on the selected ancestry. A request to compact, a failed or cancelled attempt and a compaction on a sibling path are not one. A Noter whose frozen entries include any entry before it runs with fresh context for the whole batch.
- **Trace** — the tool that walks addresses: knowledge → its facts → the source turn; exact tagged versions (`K7#qfzt`), per-identity history (`K7@v2`, `K7@v2..v4`, `K7..`); a fact's later strong negations (`F101..`). Also the project name.
- **Search** — lexical lookup over facts and knowledge (and optionally a session's raw) returning addresses. No hit does not mean absent.
- **Global preference** — one of the defaults the Pi menu's Settings entry saves under `trace-memory` in the resolved agent settings file: Noter and Consolidator execution modes, each phase's model and subagent thinking level (Dreamer is always a fresh subagent), and the closed-session scope that decides whose finished sessions this executor may work on. They are the existing canonical configuration keys, not a second system; a project or environment layer still overrides them, and a saved value reaches tasks admitted afterwards while running tasks keep the mode, model, thinking level and scope frozen with them. Database Knowledge budgets appear in the same Settings screen but are not global preferences and never write that file.

## Process

- **Logical task** — one target session, phase and stable oldest selected backlog item: a source entry for Noting, a fact for Consolidation, or the frozen pool range's first revision for Dreamer. Three terminal business failures of the same task disable memory; success resets that task and explicit on resets every target streak. Reopen does not reset it. Cancellation is not a business failure. Dreamer ranges end once; a catchup retry admits a new range without replaying committed changes. Failure accounting uses the oldest pending revision, not the new range's ID. Residual budget excess is not failure.
- **Disposition** — an operation or reasoned skip recorded by a model. Dreamer processing covers skips and own output, not the entire frozen range; a timeout is not a completed maintenance pass. Consolidation retains explicit skipped-fact reasons but has no second-round accounting check.
- **NEAR** — the Noter's lexical review of candidate facts against earlier same-path facts. Similarity alone establishes no relation. Consolidation has no corresponding second round.
- **Fork** — inherited-context execution: the run happens in a child of the conversation itself, continuing from its persisted state. The execution mode, never the evidence path called branch. Runs recorded before this name existed carry the old spelling and are read as legacy request-copy execution.
- **Subagent** — fresh-context execution: the run happens in a private child prepared from the frozen material alone. The alternative to fork.
- **Material** — the frozen parts one memory run works from: the active knowledge, the historical facts, the compressed Raw views of its selected entries, its own range and the budget receipts. A task freezes it once; both execution modes read that one.
- **Increment** — what an inherited-context run adds to a conversation that already carries the raw, the delivered facts and the injected knowledge: its instruction, the range, and the head reply and source index, or the exact fact list. Never a second copy of the material.
- **Run record** — an audit record for noting, consolidation, dreaming or manual work holding the exact input sent to the model, the prompt version, the model, the execution mode, and the output. Knowledge revisions point at the run that produced them.
- **Worker log** — the child session's own JSONL, written by the host itself, named in the run record as `nativeLog`. On Pi it is by default a direct child of the agent's `sessions/trace-memory` directory — one level under Pi's session root, where external daily-cost readers look, and where Pi's all-session browser lists it. On CC it is the worker's native Claude Code session, one directory under Claude Code's own `projects` root, named for `worker.cwd` — where claude-powerline's daily cost counts it like any other session. Neither host moves logs written under an earlier layout.
- **Completion level** — the prefix on an event fact: completed (result evidence visible), reported (claimed only), dispatched, attempted.
- **Local handle** — `$n`, the n-th fact of the current noting batch, used for in-batch relations before ids exist; the writer resolves it.
- **Commit durability** — the database trades some crash safety for a responsive event loop: an OS crash or power loss can roll back the most recently committed transactions (a few seconds of Raw, facts or knowledge); a process crash alone loses nothing already committed. Recovery needs no operator step: on restart, each host re-imports any Raw missing from the database out of its own native transcript or session, and Noting/Consolidation/Dreaming work whose commit was rolled back is pending again, exactly as if it had never run. A rolled-back run's spend record is lost with it.

## Languages

Memory content is written in the language of the conversation. Everything that is work — code, comments, docs, prompts, subagent briefs — is English.
