# Trace Memory — domain glossary

Terms only. No implementation detail. When a term here conflicts with usage in code or prompts, this file wins and the other side is fixed.

## Layers

- **Raw** — the conversation as the host recorded it: user messages, tool calls with results, assistant text. The only source of truth. Never edited.
- **Source entry** — one completed native conversation message: user text, assistant content with tool calls, or a tool result. Identity is its native id within the session lineage, never its text. It belongs to a Turn and receives an immutable Turn-local E ordinal; branch gaps never renumber it. The host normalizes ordered content blocks once for rendering and exact citation validation. Plugin injections and summaries are never sources.
- **Compressed Raw view** — the shared, bounded head/tail excerpt of one source entry, in Pi's compaction line shape with stable whole-entry addresses with role filters (`[T<n>#E<m>@user] user: …`, `[T<n>#E<m>@assistant] <tool>(<key>=<JSON>)`, `[T<n>#E<r>@observation] <tool> <status>: …`) and honest omission counts in one marker family (`[... N characters truncated]`). One view everywhere, under one profile of three independent budgets: `E` for the whole entry, `C` for each tool-call part, `R` for each tool-result part, each including the labels, syntax and markers inside it. A marked compressed view is visible Raw whether or not it was truncated. The original Raw remains available through `trace://raw/S<n>/T<t>#E<k>`, uncompressed under the same labels. Host-native Read controls ordinary file pagination; exact entries, session knowledge and compaction views are whole, except in CC fresh workers where SDK Read retains its native cap.
- **Turn** — one user message and everything it triggered until the next user message. A compaction is also recorded as a turn, with no facts.
- **Fact** — one topic's titled slice over a continuous stretch of conversation, restoring the episode rather than a decontextualized conclusion. A slice may span Turns and retains its question, reasoning, evidence and revision together. Each contributing whole entry has one authored segment; core orders segments by the selected source path, joins their text into the body and derives each source's role (user, assistant, observation). The earliest source Turn owns a new fact. Its title identifies the episode; assistant prose names the original harness. Optional support/negate relations remain annotations. Legacy bodies, sources, category, actor, status and quote are unchanged. Every writer is held to the length target (ticket 144, unit 145): the title at `writing.titleWords` (20) and the body, its source segments counted one by one and summed, at `writing.bodyWords` (200); existing facts are not rewritten. Material windows charge the complete rendering. Manual writes commit immediately.
- **Fact group** — automatic material displays selected complete facts under their owning Turn: Turns in chronological start-time order, facts in ascending F-id order. A group need not cover its entire Turn. A direct Turn read instead shows each fact with a contribution there, restricted to that Turn's segments; a legacy fact without segments is shown whole. Neither view changes ownership, citation scope or processing membership.
- **Knowledge** — one topic's continuing understanding grounded in facts, retaining enough background, reasons, evidence strength and retrieval context to be understood outside the original discussion. Granularity follows importance and joint maintainability, not object count or category differences. Newly authored category fields use five categories: constraint, understanding, goal, open, reference. Legacy mechanism/term group under understanding and dispute under open without rewriting stored revisions; exact edits inherit omitted metadata unchanged. An update authors a full replacement or ordered exact edits of its tagged base. Each immutable revision stores the complete resulting body (or archival state) and exact lineage. Every version has a title (ticket 144); legacy versions have none, are never rewritten, and show their body's leading characters, cut to the title target, as their title. A new live version always ends with a title: `create` and split children give one, an `update` or `merge` inherits its base's and a base without one requires it. Title and body are held to the length target (`writing.titleWords` 20, `writing.bodyWords` 200) for the Noter, the Dreamer and manual writes alike, each split child and each update's resulting body included.
- **Length target** — the length a writer is told for a title (20) and a body (200), counted in **units** (ticket 145): each CJK character is 1 and each run of letters and digits is 1, an inner `.`, `-` or `/` keeping a path or identifier whole; punctuation and spaces are 0. Every check counts the same unit and refuses only beyond the target plus 10%, rounded up (22 and 220); the prompts name the target alone. Budgets, triggers, the curate prefix cap and injection stay in tokens.
- **Supports** — the facts directly grounding one revision. A revision applies when its own scope admits the reader and every direct support belongs to the revision's scope and to its fact owner's current foreground. Lineage is provenance, not a recursive applicability condition. Evidence-driven changes store exactly their submitted supports. When a trusted Dreamer submits an empty list, core materializes the exact parents' supports at commit: one parent's set for update/archive/split and the union of both sets for merge. Migration fills historical empty sets in parent-before-child order; a revision stays empty only when its entire ancestry is empty.
- **Knowledge version address** — bare `K12` selects current; `K12#qfzt` matches an exact immutable version and is required for mutation bases. Per-identity `K12@v3` ordinals include all branches and never renumber with scope. Complete model bodies, including complete Changed diffs, carry tags, continued bodies only after their final fragment; committed update/merge/split receipts carry the newly authored versions' tags. Previews, state notices and other body-free receipts carry no tag. Reads hold no grant ledger. Human audit, database keys and actual-delivery carriers retain global commits.
- **Knowledge lineage** — immutable revision history: creation has no parent; update/archive have one; merge names a primary, which keeps its identity and gains the merged version, and consumes one or more other identities; split keeps the named item as its primary part (a new version of the same identity) and atomically creates one or more new Knowledge identities recorded as split from it, without archiving it. Effective resolution is stateless: among branches whose revisions' direct facts currently apply, the later committed conflicting branch has priority; an earlier branch returns when the later branch stops applying. The same resolved graph supplies reads and atomic stale-base write checks, so consumers never expose an effective fork. Archives participate before body filtering. Parent and merge/split links preserve provenance without inheriting applicability.
- **Trigger origin** — the target memory-session identity plus one triggering `source_entries.id`, frozen for execution and run audit. An explicit trigger is used when supplied; otherwise choose the last entry on the target ancestry. Later foreground navigation does not move it; historical absence stays unknown. Existing stored multi-id origins remain unchanged and their final id is the trigger. Origin is provenance, not knowledge validity or permission to write a stale base.
- **Reason** — the commit message of one knowledge commit: what changed and why it was chosen. It is not a durable claim and has no authority of its own; it establishes no evidence, scope, applicability, accounting coverage or completion level, and addresses written in it are never read as citations.
- **Topic** — a subject label on one knowledge revision: the module, component or domain the conclusion is about, beside its category. Labels are free strings, trimmed, deduplicated and versioned with the revision that carries them; several may apply and none is required. Classification only — a topic changes no scope, evidence permission, lifecycle or eligibility, and sharing one merges no knowledge.
- **Noting** — one batch is two independent runs, `write` then `verify`, that hand work over through two workspace files (`facts.md`, `knowledge.md`, in the shared block format) under the run's workspace directory. Task 1 records the batch's facts and knowledge create/update; task 2, started with byte-identical system prompt, tools and task text, checks and corrects the files, facts first. Both call `check` (it names the task and the two files and returns problems and measured lengths); each task has two steps (facts, then knowledge) with their own prompts, delivered through the step's first `check` result, a repair or the step-advance message; the stop hook checks the current step with one repair per step, step 2 may not change the facts file that passed step 1, and a step's second failure fails the run. Nothing is published before task 2 passes; then one short transaction publishes both layers, frozen Raw progress and successful execution. A task 1 failure keeps nothing; a task 2 failure keeps task 1's files in a hand-off row, and the next trigger resumes with task 2 on the same batch. Every run that does not finish normally is one failure toward the three-failure switch-off, whichever task it stopped in. A valid tagged predecessor advanced by a visible effective descendant converts update to an annotated create or archive to an audited no-op, without weakening evidence or scope checks. Each persisted main-session entry checks for 10,000 pending compressed-view tokens; an import checks once at its final selected head, triggered by its newest persisted entry. Historical bootstrap at startup, session-start restore or enabling memory follows that rule only when new selected entries were persisted; fully imported resume, zero-append scans, sibling-only imports and Pi tree navigation create no check. Run completion grants no automatic opportunity, and busy checks accumulate no owed runs. A run processes the oldest whole-entry prefix within 10,000 tokens and the model context capacity. Thinking-only entries contribute no material or pending tokens but remain processing members and are marked processed on publication. Fresh material reuses compact assembly at the batch's last exact entry, with processed-Raw refill disabled and preceding facts and current visible Knowledge retained. The Noter always runs fresh (ruling 2026-10-22): a fork's prefix is the main conversation, not the compaction memory the Noter starts from. A partly processed Turn may still have pending entries.
- **Dreaming** — maintenance of the knowledge a session sees, for quality and readability, never to fit a budget. One run is one admission, claim and execution of three tasks in order, each ending in a file a host's model writes and `check` verifies: **curate** (per category, in one conversation over the whole pool, proposing changes of the run's one operation, which rotates per project update → merge → split → archive; Dreaming never creates knowledge and curate applies nothing), **verify** (gives every numbered proposal one verdict, confirm, edit or revert, against facts, Raw and the repositories the session worked in, and only then are the confirmed and edited operations applied) and **classify** (scores items; fresh context per pass). A run finishes with its last classify pass, which advances the project's rotation if the run's operation is the one due; a failure after that commit changes nothing. A run is due when the Noter's knowledge operations (each create or update, a second update of one item counting again) not yet covered by a Dreamer pass reach the configured trigger (30 by default; manual writes and the Dreamer's own changes never count), or when a hand-off row asks for a retry or resume. Each main-session entry end checks, independently of Noting under the existing seats; imports use the same final-selected-head checkpoint and bootstrap/navigation boundaries as Noting. One run covers all of the session's pools; another automatic run requires a later entry end. A task that passed leaves a hand-off, so a failure or stop resumes at the first task or category not done; a failed run is retried at the next check, with no wait for a threshold and no count reset, and three consecutive failures switch memory off as the Noter's do (a lost claim counts; a stop, memory off or shutdown does not; only a finished run resets the streak). A task with nothing to do (no change to verify, nothing to score) completes without a model call. Exact version tags, current visible bases and the live claim fence guard each operation; a stale base is refused for that operation only and left for the next run. A configurable wall-clock bound (thirty minutes by default) applies to each task.
- **Coverage** — the exact per-version, per-pool processing record (`knowledge_processed`) a passed Dreamer verify writes for the versions curate's batches showed and the verify pass wrote. A version is covered only in the pool that owns it; a project move leaves it uncovered in its new pool. Uncovered versions the Noter wrote make the Dreamer due. Nothing is covered on failure.
- **Score** — a knowledge item's importance, 1 to 100, set by classify for the version it was shown and kept when the item later changes, until classify scores it again. Curate shows unscored items whole and, when its prefix is over its cap, keeps only the title of the lowest-scored. Scores are stored beside, not in, the version chain.
- **Consolidation** — retired extraction stage. Historical C runs, costs, logs, actor labels and processing rows remain readable as C; no new worker, seat, trigger or configuration exists. Historical unconsolidated facts are neither cleared nor replayed by retirement. N now owns knowledge create/update/archive; merge and split remain D-only. Manual knowledge writes allow fact-backed create/update/archive.

## Relations (annotations, never derived state)

- **Support** — a newer fact affirms an older one: adoption, approval, agreement, an answer, a restatement, execution of a ruling.
- **Negate** — a newer fact opposes or invalidates an older one: withdrawal, veto, found wrong, a new state overturning the old, doubt, objection, evidence that does not fit.
- **Strength** — the Noter's confidence that the relation holds: *strong* when the raw states it, *weak* when inferred or partial. Attribution comes from each source's derived role and authored segment, or the saved actor on a legacy fact, not from the strength.
- No fact is ever hidden or retired by a relation. Automatic and path-scoped collection material shows a relation only when both Fact endpoints are on the selected path. An explicit `F<n>` trace remains unrestricted and marks relations whose other endpoint is inapplicable there. Relations show N and D the recorded annotations; the reader judges their bearing on the claim.
- **Dispute** — a historical knowledge category for conflicting accounts without a ruling; rendered as open. Not a fact relation.

## Scope and attribution

- **Enrollment** — the durable enabled or disabled participation of one memory-session identity, changed by `/trace on` and `/trace off` (in Pi) for that identity alone, immediately and without a reload. Explicit intent overrides its derived default; shared forks and clones share the switch. Disable pauses future work and injection while retaining memory and unrestricted reads. There is no global participation switch.
- **Baseline** — the installation-scoped instant of the plugin's first successful initialization, retained across restarts and upgrades. Only native sessions created strictly after it default enabled; unknown or malformed creation times default disabled.
- **Session** — one host conversation. Gets an id only once an assistant reply exists. Claude Code's `/clear` ends one session and starts a new one (102), as an exit followed by a startup in the same directory.
- **Lineage cursor** — one native foreground within a memory session, persisted as `(session, lineage) → (branch, head)`. Each lineage moves independently and retains its cursor while closed; reopening adopts the same key. A session with no cursor treats all stored paths as active, while any recorded cursor makes only the recorded lineages' paths active. Fact liveness requires one complete cursor path to contain its Turn, source Turns and bound entries; membership is never assembled across sibling paths.
- **Executor** — an enabled active host runtime with N and D slots only. On CC it serves its Claude Code process's current native session: when the process moves to another (`/clear`, an in-process `/resume`), the executor leaves the old one as on exit and attaches to the new one as at startup. N prefers its own eligible work before borrowing a closed tail. D shares one database-wide seat and processes the pools visible at the executor's node, never a borrowed closed-session task.
- **Closed-session scope** — the Noting borrowing policy: off leaves tails pending, project allows the same project (default), and global allows any project. Borrowing selects only retained active lineage cursor paths (including ancestors up to each exact head); abandoned siblings stay pending until reactivated. A session without cursors retains all-path compatibility, while an invalid cursor fails the borrowed scan. The executor must be enabled and open. This policy does not change current-session work, manual catchup or Dreaming.
- **Target** — the memory session and branch whose evidence a worker processes. Its project, costs, commits, progress and deliveries remain its own even when another executor hosts the worker.
- **Claim** — exclusive ownership of one target's phase across branches and executors, identified by an executor, a token and a thirty-minute expiry. Current ownership fences commits; reopening immediately replaces another executor's token. An unexpired Dreaming claim also occupies the database's sole Dreamer seat. Cancellation closes the task's tools and workspaces immediately (the cancellation fence) and expires the claim at once; a late write or pass end changes nothing. Token, expiry, takeover and project checks remain required.
- **Closed** — a session marked by normal shutdown and cleared on restore. For CC, every native SessionEnd, `/clear`'s included (102), closes its bound lineage without requiring executor termination or complete tail import; the core session stays open while another lineage is live (sessions linked on `/clear` before 102). A stale native process cannot close a reopened session. MCP executor shutdown alone, a crash or an expired claim does not establish closure.
- **Project** — the unit that shares knowledge. Shared membership comes from an explicit user command (`/trace project <name>` in Pi, `trace project <name>` in CC) or, for a new session, from its directory: the session records its repository root (the parent of git's common dir, so worktrees share it) or the real path of cwd, and joins the project that directory's recorded sessions already belong to when that is exactly one (62); none or several keep the session's own project; the home and temporary directories never key; sessions from before 62 record no directory and count for nothing; an explicit command always wins. The same name in the same database identifies the same project. Changing project ownership requires the declaring session to have no running N/D and no reached N/D trigger, including the session's Dreamer overflow and summed pending. Refusal starts no work and queues no declaration. Other sessions do not block the move; their in-flight writes still face ordinary authority checks. Moved-in project revisions become pending again in the destination, including on a return move, by clearing only their destination processing records in the relabel transaction. Order follows revision creation, not move time. Unrelated destination records and global/session processing records stay unchanged.
- **Scope** of a knowledge item — `session` (holds only in that session), `project`, or `global` (about the user, the environment, general working method).
- **Knowledge base policy** — one transactional database row (`knowledge_base_policy.base_tokens`, default 20k) that injection and compaction read as the Knowledge base. It decides no Dreamer trigger, success or archive. Settings shows it as one "Knowledge base" row and edits the database, not Pi files. The older Global/Project/Session pool budgets (`knowledge_budget_policy`) stay in their table, unread; the base starts as their sum.
- **Manual catchup** — `/trace catchup`'s finite, explicit Noting drain of the current enabled session's selected branch: bounded subagent batches below the normal Noting trigger, within a frozen entry-id boundary. Start and successful completions check N/D: N drains its frozen boundary and D uses ordinary due rules. N has one seat per session and D one database-wide seat. Busy work is not queued or adopted. Completion requires an exhausted frozen Raw backlog, no due D, and no owned work still running; below-threshold knowledge may remain. Empty or dropped results do not re-arm the loop. A failed catchup step immediately retries the same phase under its existing boundary, without checking the other phase; ordinary logical-task failure accounting turns memory off after three consecutive failures and ends the drain. Cancellation ends the drain. Stop/off/shutdown/path changes fence further launches. Later Raw never extends the frozen boundary.
- **Stop** — `/trace stop`'s cancellation of one executor's background work (its own manual catchup plus any ordinary or borrowed work), reusing the same claim, token-fence and cancellation machinery as shutdown. It never disables enrollment, never edits configuration and never touches another executor's claim.

## Reading

- **Foreground Knowledge delivery** — current visible exact versions minus the delivered state recorded in the per-node delivery records on the selected path: the latest compaction's baseline plus later deliveries (97). Facts and Raw never substitute for a Knowledge body. Pi may publish one Knowledge-only hidden message at its ordinary prompt entry; CC publishes at startup/resume/clear, in its own compaction of a main-session manual or automatic compaction through the function hook (after the native one when that compaction is not built), and at UserPromptSubmit for missing-body recovery; SessionStart(compact) does not inject. State notices are separate, tagless and reveal no reader-invisible successor. The Knowledge base charges the accumulated base cost of the deliveries recorded on the path, and the context's one temporary allowance the temporary cost (`temporary_tokens`); every delivery counts, including repeats of one version. A version delivered as a title only is recorded as such and does not hide a later body. A publication is delivered when it is emitted: every part of a successfully staged publication counts, including a part Claude Code persisted to a file. Transcript carriers are not read back. Budget omissions and failed staging establish no delivery.
- **Injection** — the same Knowledge renderer and exact-version foreground predicate; compaction separately carries knowledge, recent facts, and pending compressed Raw views. Knowledge is grouped by category in glossary order (`constraint`, `understanding`, `goal`, `open`, `reference`; legacy `mechanism` and `term` render in `understanding`, `dispute` in `open`), each group opened by a `## <category> (<n>)` line and omitted when empty, each item retaining its category label, items inside a group ordered by last change, oldest to newest (132). A common header explains this, that position does not compare items across categories, and that a later claim on the same object within a category stands until merged; selection is by score (see Score), not by age. CC SessionStart stages one immutable 24-slot snapshot, keyed on the event, for Hooks starting within its producer's original 55-second window; database commits do not invalidate eligible readers. A later invocation outside that window renders afresh. Staging records the delivery (97). Within that snapshot, knowledge is packed in that category-then-oldest order with next-fit, never backfilling earlier segments; a group may continue into the next segment, and each segment's block groups and counts its own items; global order is the existing segment number followed by position within the segment, not native arrival order. Facts and Raw may fill gaps. Every capacity check prices the same final grouped carrier that is emitted, headers included. Final part Knowledge costs include repeated recency framing, state notices and Knowledge omission receipts; their sum must fit the remaining Knowledge base, and the framing only temporary items need must fit the remaining temporary allowance. The slicer trims in core's selection order (base items first, then temporary ones) with the two caps kept apart; each slice's header records its base cost (`t`), its temporary cost (`u`) and its title-only versions (`i`). Facts, Raw and the separately bounded host envelope are excluded. Budget reduction removes the lowest-ranked optional bodies before state notices without backfilling earlier segments.
- **Score** — a Knowledge item's 1-100 classify score (the Dreamer's classify task; null until classified). The Knowledge base takes scored items whole in score order, ties newer version first; the first scored item that does not fit stops the base and the rest become titles (user ruling, 2026-10-22). A changed item keeps its score.
- **Compaction** — replacement of the context with the injection block. The core allocator renders one frozen path snapshot without a model and reports pending Raw omissions. A host uses the custom replacement only when every pending Raw entry fits the Raw base plus temporary allowance; otherwise it compacts natively (133 R1). Unexpected host-caught errors, including live-task lookup errors, also leave compaction to the host. Omitted Raw stays pending; compaction starts no extraction worker. Pi and Claude Code main-session manual and automatic compactions use this policy when the hooks are loaded (102); a plugin's, a precomputed or a subagent's compaction stays Claude Code's own. A `/compact` with instructions (non-empty after trimming) stays native on both hosts (130). Claude Code then appends the Knowledge supplement; Pi recovers Knowledge through ordinary delivery at the next prompt. A custom replacement keeps no original message: the turn in flight is its newest Raw.
- **Material window** — a compaction part: Knowledge has a database-derived 20k base and facts/Raw have configurable 10k bases (`compaction.factsTokens`, `compaction.rawTokens`). The one temporary allowance (`compaction.temporaryTokens`, 10k by default, independent of triggers) replaced the Knowledge-only shared allowance (144). Pending Raw borrows from it; already-noted Raw and all full facts remain inside their own bases. Raw selection, fact coverage and entry rendering are unchanged. Framing and receipts count in their owning budgets; the fixed reading guide is outside the windows and allowances but inside delivered context. Bases never lend to one another. Fresh Noter Knowledge uses the base and the temporary allowance.
- **Temporary allowance** — `compaction.temporaryTokens`, 10k by default, one per context (144): a compaction, `/clear` or session start begins a new one and each delivery records what it charged. Filled in order: pending Raw overflow first (compaction only); then unscored Knowledge whole, newest first; then titles of scored Knowledge that missed the base, in score order (`[K12#tag] [category/scope] (title only) <title>`); then human user entries within `compaction.userTurns` (100) and uncovered fact titles within `compaction.titleTurns` (100) together, turn by turn (each turn's user entries, then its titles), so both reach the same depth while the allowance lasts. Both reaches include the anchor and count its path's turns; a kind past its reach drops out and the other continues alone; no older material fills spare room. User entries use the normal middle-cut renderer with `compaction.userEntryTokens` (300); excerpts and titles are context, not full-body coverage. The first item that does not fit stops both kinds. Main compaction and Noter share the allocator; the Noter's anchor is its batch's newest turn and its frozen batch fits its own Raw base, so its temporary allowance holds only user words and titles. Each kind stops at its first misfit and the next kind continues. Ordinary prompts spend what the allowance has left, new Noter knowledge included (user ruling, 2026-10-22). Capacity negotiation trims this allowance before full historical facts. Compaction alone may append live running tasks outside all budgets.
- **Refill** — superseded by the single allocation under Material window (73): already-processed Raw fills only its own base remainder after pending Raw; this refill is disabled only for Noting's exact pending batch. Facts fill their own window regardless of historical processing. A fact is excluded only when its nonempty complete source-entry binding is fully covered by the final Raw span or retained originals/recognized bounded carriers; this applies to unconsolidated facts too, which stay pending in the store. Complete bindings not wholly covered by Raw stay eligible; missing bindings or inconsistent stored segments are data corruption, not a coverage fallback. A discarded summary proves no retained coverage. Omitted items start no work, reset no processing and claim no supplied IDs.
- **Memory material coverage invariant** — withdrawn by 73: bounded material is not semantic losslessness, and an ID or omission receipt is not a body. The core trace view may truncate Raw and facts with receipts without changing processing. Under 133 R1, an actual host compaction delegates to native when pending Raw would be omitted; that Raw remains pending for Noting.
- **Compaction boundary** — the last compaction the host successfully persisted on the selected ancestry. A request to compact, a failed or cancelled attempt and a compaction on a sibling path are not one. A Noter whose frozen material entries include any entry before it runs with fresh context for the whole batch; thinking-only processing members do not decide this.
- **Trace** — the internal address renderer and human audit API, not a model-callable tool. Models read memory through `trace://`; event ranges, comma lists and old trace-address path fallback are removed. Internal historical source parsing and stored citations remain unchanged.
- **Search** — lexical lookup over knowledge (every version, marked current, superseded or archived), facts and Raw, one line per hit; a Raw hit's text is the exact Read of its address. `code` runs a script over the structured hits in a sandbox, and an output past the cap is saved to a file the caller's own Read can open, in every host and worker. No hit does not mean absent.
- **Memory files** — memory read at `trace://` addresses, a read-only virtual namespace. Exact node views use `trace://<layer>/S<n>[/T<t>]`: `knowledge` is a fresh context's knowledge, `compact` is manual compaction material without a continue sentence, `facts` contains Turn contributions and uncovered-entry paths, and `raw` is the compressed overview. Only raw accepts `#E<k>` (requires T, whole entry) and `@user`, `@assistant` or `@observation` (role check). Omitted T uses the current selected head; explicit T prefers that containing branch, otherwise the containing source path with greatest HWM entry id then path id. `trace://S<n>` lists one Turn per line with its facts/raw paths. K/F/version/history views and root knowledge identity lists remain. Recursive Grep searches facts and whole Raw leaves, never overview duplicates or knowledge/compact injections; knowledge-all still searches all immutable versions. Reading records no delivery or state. Ordinary Read and Grep use each host's limits; a continuation reads the same `trace://` path with offset/limit and renders again, like an ordinary file that may change between calls. Rendered backing paths are not exposed to the model. Session knowledge and compaction views return whole; Pi delegates ordinary reads through native operations. One shared reading guide, at most 200 estimated tokens, appears once per injection/material; root lists the session-list entries without expanding the guide. Writes under `trace://` are refused.
- **Retrieval policy** — the text saying when to look memory up (only when the answer would change the next step), apart from the reading guide, which teaches format. Each run sees it once, in its system prompt (a Claude Code main session through the plugin's `prompt.compose` hook, only with function hooks loaded and memory on); a fresh worker (N or D) gets it too. With the guide it stays within 500 estimated tokens.
- **Global preference** — one of the defaults the Pi menu's Settings entry saves under `trace-memory` in the resolved agent settings file: N/D models and subagent thinking levels, and the closed-session scope that decides whose finished sessions this executor may work on. They are the existing canonical configuration keys, not a second system; a project or environment layer still overrides them, and a saved value reaches tasks admitted afterwards while running tasks keep the model, thinking level and scope frozen with them. Database Knowledge budgets appear in the same Settings screen but are not global preferences and never write that file.

## Process

- **Logical task** — one target session, phase and stable backlog key: the oldest selected source entry for Noting, none for the Dreamer, whose task is its session. An automatic failure can retry only at a later entry end; manual catchup retains its immediate same-phase retry. Three terminal business failures of the same Noting task disable memory; success resets that task and explicit on resets every target streak. Reopen does not reset it. Cancellation is not a business failure. A Dreamer failure retries at the next entry end with its operation count kept; three consecutive Dreamer failures disable memory as the Noter's do, and only a finished run resets that streak (146).
- **Disposition** — what a model's file asked of one knowledge item and what became of it: an operation applied, or refused as stale and left for the next run. A timeout is not a completed maintenance pass. Historical Dreamer skips and Consolidation skipped-fact reasons remain in old run audits.
- **NEAR** — historical Noter lexical-review audit only. New Noting has no similarity scan, feedback or mandatory relation review; old audit records remain readable.
- **Subagent** — fresh-context execution: the run happens in a private child prepared from the frozen material alone. The only execution mode of N and D.
- **Material** — the frozen parts one memory run works from: the active knowledge, the historical facts, the compressed Raw views of its selected entries, its own range and the budget receipts. A task freezes it once.
- **Run record** — an audit record for noting, consolidation, dreaming or manual work holding the exact input sent to the model, the prompt version, the model, the execution mode, and the output. Knowledge revisions point at the run that produced them.
- **Worker log** — the child session's own JSONL, written by the host itself, named in the run record as `nativeLog`. On Pi it is by default a direct child of the agent's `sessions/trace-memory` directory — one level under Pi's session root, where external daily-cost readers look, and where Pi's all-session browser lists it. On CC it is the worker's native Claude Code session, one directory under Claude Code's own `projects` root, named for `worker.cwd` — where claude-powerline's daily cost counts it like any other session. Neither host moves logs written under an earlier layout.
- **Completion level** — the prefix on an event fact: completed (result evidence visible), reported (claimed only), dispatched, attempted.
- **Writer schema** — the foreground `note` and `memory` tools write one fact or one knowledge operation at once. The Noter does not use them: it writes files.
- **Local handle** — `$n`, the position of a fact in a manual or workspace write; a workspace file names its facts by label (`f1`), and knowledge `supports` and fact `support:`/`negate:` relations resolve through a label-to-F map inside terminal publication, never by rewriting prose.
- **Commit durability** — the database trades some crash safety for a responsive event loop: an OS crash or power loss can roll back the most recently committed transactions (a few seconds of Raw, facts or knowledge); a process crash alone loses nothing already committed. Recovery needs no operator step: on restart, each host re-imports any Raw missing from the database out of its own native transcript or session, and Noting/Dreaming work whose commit was rolled back is pending again, exactly as if it had never run. A rolled-back run's spend record is lost with it.

## Languages

Memory content is written in the language of the conversation. Everything that is work — code, comments, docs, prompts, subagent briefs — is English.
