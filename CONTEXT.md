# Trace Memory — domain glossary

Terms only. No implementation detail. When a term here conflicts with usage in code or prompts, this file wins and the other side is fixed.

## Layers

- **Raw** — the conversation as the host recorded it: user messages, tool calls with results, assistant text. The only source of truth. Never edited.
- **Source entry** — one completed native conversation message: user text, assistant content with tool calls, or a tool result. Identity is its native id within the session lineage, never its text. It belongs to a Turn and receives an immutable Turn-local E ordinal; branch gaps never renumber it. The host normalizes ordered content blocks once for rendering and exact citation validation. Plugin injections and summaries are never sources.
- **Compressed Raw view** — the shared, bounded head/tail excerpt of one source entry, in Pi's compaction line shape with stable whole-entry addresses with role filters (`[T<n>#E<m>@user] user: …`, `[T<n>#E<m>@assistant] <tool>(<key>=<JSON>)`, `[T<n>#E<r>@observation] <tool> <status>: …`) and honest omission counts in one marker family (`[... N characters truncated]`). One view everywhere, under one profile of three independent budgets: `E` for the whole entry, `C` for each tool-call part, `R` for each tool-result part, each including the labels, syntax and markers inside it. A marked compressed view is visible Raw whether or not it was truncated. The original Raw remains available through `trace://raw/S<n>/T<t>#E<k>`, uncompressed under the same labels. Host-native Read controls ordinary file pagination; exact entries, session knowledge and compaction views are whole, except in CC fresh workers where SDK Read retains its native cap.
- **Turn** — one user message and everything it triggered until the next user message. A compaction is also recorded as a turn, with no facts.
- **Fact** — the finest topic's titled slice, keeping its narrative and grouping same-topic statements even when not adjacent. A slice may span Turns and retains its question, reasoning, evidence and revision together. Each contributing whole entry has one authored segment; core orders segments by the selected source path, joins their text into the body and derives each source's role (user, assistant, observation). The earliest source Turn owns a new fact. Its title identifies the episode; assistant prose names the original harness. Objects use full current names and appear in the body. Optional negate/caused_by relations remain annotations; stored legacy support relations remain readable. Legacy bodies, sources, category, actor, status and quote are unchanged. Every writer is held to the length target (ticket 144, unit 145): the title at `writing.titleWords` (20) and the body, its source segments counted one by one and summed, at `writing.bodyWords` (200); existing facts are not rewritten. Material windows charge the complete rendering. Manual writes commit immediately.
- **Fact group** — automatic material displays selected complete facts under their owning Turn: Turns in chronological start-time order, facts in ascending F-id order. A group need not cover its entire Turn. A direct Turn read instead shows each fact with a contribution there, restricted to that Turn's segments; a legacy fact without segments is shown whole. Neither view changes ownership, citation scope or processing membership.
- **Knowledge** — one topic's continuing understanding grounded in facts, retaining enough background, reasons, evidence strength and retrieval context to be understood outside the original discussion. Granularity follows importance and joint maintainability, not object count or category differences. Newly authored category fields use five categories: constraint, understanding, goal, open, reference. Legacy mechanism/term group under understanding and dispute under open without rewriting stored revisions; exact edits inherit omitted metadata unchanged. An update authors a full replacement or ordered exact edits of its tagged base. Each immutable revision stores the complete resulting body (or archival state) and exact lineage. Every version has a title (ticket 144); legacy versions have none and are never rewritten; they show `(no title)` in a whole item's header, `(opening only)` and their body's opening with `…` where only a title is shown, and a marked `(no title)` label elsewhere (ticket 153). A new live version always ends with a title: `create` and split children give one, an `update` or `merge` inherits its base's and a base without one requires it. Title and body are held to the length target (`writing.titleWords` 20, `writing.bodyWords` 200) for the Noter, the Dreamer and manual writes alike, each split child and each update's resulting body included.
- **Length target** — the length a writer is told for a title (20) and a body (200), counted in **units** (ticket 145): each CJK character is 1 and each run of letters and digits is 1, an inner `.`, `-` or `/` keeping a path or identifier whole; punctuation and spaces are 0. Every check counts the same unit and refuses only beyond the target plus 10%, rounded up (22 and 220); the prompts name the target alone. Budgets, triggers, a group's input allowance and injection stay in tokens.
- **Object** — a specific thing a developer of this project identifies at once by its full current name, appearing case-insensitively in the fact's body, not a class word such as project, file or test; a ticket, commit or session must be accompanied by the mechanism it implements or the problem it solves. Knowledge objects are derived from distinct facts cited along its exact ancestry since the last split, ranked by how many facts mention each object; they are not authored knowledge content.
- **Code-file link** — an explicit `path` or `path#symbol` address bound to one knowledge version. A symbol link tracks the declaration's text between its verified commit and repository HEAD; whole-file links retain file-level change detection. No mapping record means “not mapped”; an explicit `None` means no code-file grounds, and a maintenance copy preserves that distinction. Curate requires symbols to exist at the repository's captured commit, shared by every group in the run, and caps whole-file links project-wide (default 5 current items per address); function addresses have no cap.
- **File verification** — a version's linked file checked at a recorded commit and time, supplied by code rather than a model. Verification is status, not content, and changing it creates no version.
- **Stale flag** — one or more reasons that a version may be outdated: a negated fact, a changed verified file, an unresolved Noter check, an unverified link or missing grounds. Setting or clearing the flag changes neither the version chain nor fact-based applicability.
- **Supports** — the facts directly grounding one revision. A revision applies when its own scope admits the reader and every direct support belongs to the revision's scope and to its fact owner's current foreground. Lineage is provenance, not a recursive applicability condition. Evidence-driven changes store exactly their submitted supports. When a trusted Dreamer submits an empty list, core materializes the exact parents' supports at commit: one parent's set for update/archive/split and the union of both sets for merge. Migration fills historical empty sets in parent-before-child order; a revision stays empty only when its entire ancestry is empty.
- **Knowledge version address** — bare `K12` selects current; `K12#qfzt` matches an exact immutable version and is required for mutation bases. Per-identity `K12@v3` ordinals include all branches and never renumber with scope. Complete model bodies, including complete Changed diffs, carry tags, continued bodies only after their final fragment; committed update/merge/split receipts carry the newly authored versions' tags. Previews, state notices and other body-free receipts carry no tag. Reads hold no grant ledger. Human audit, database keys and actual-delivery carriers retain global commits.
  The stage-4 Noter workspace may instead name a bare `K12` for a duplicate update or unresolved flag; Core binds its current visible version and rechecks it at publication.
- **Knowledge lineage** — immutable revision history: creation has no parent; update/archive have one; merge names a primary, which keeps its identity and gains the merged version, and consumes one or more other identities; split keeps the named item as its primary part (a new version of the same identity) and atomically creates one or more new Knowledge identities recorded as split from it, without archiving it. Effective resolution is stateless: among branches whose revisions' direct facts currently apply, the later committed conflicting branch has priority; an earlier branch returns when the later branch stops applying. The same resolved graph supplies reads and atomic stale-base write checks, so consumers never expose an effective fork. Archives participate before body filtering. Parent and merge/split links preserve provenance without inheriting applicability.
- **Trigger origin** — the target memory-session identity plus one triggering `source_entries.id`, frozen for execution and run audit. An explicit trigger is used when supplied; otherwise choose the last entry on the target ancestry. Later foreground navigation does not move it; historical absence stays unknown. Existing stored multi-id origins remain unchanged and their final id is the trigger. Origin is provenance, not knowledge validity or permission to write a stale base.
- **Reason** — the commit message of one knowledge commit: what changed and why it was chosen. It is not a durable claim and has no authority of its own; it establishes no evidence, scope, applicability, accounting coverage or completion level, and addresses written in it are never read as citations.
- **Topic** — a subject label on one knowledge revision: the module, component or domain the conclusion is about, beside its category. Labels are free strings, trimmed, deduplicated and versioned with the revision that carries them; several may apply and none is required. Classification only — a topic changes no scope, evidence permission, lifecycle or eligibility, and sharing one merges no knowledge.
- **Noting** — one batch passes four independent stages: extract facts, check facts, write knowledge, check knowledge. A check whose file is valid `## none` passes without a model call, including on resume. Other check stages receive code-retrieved related facts or knowledge, read the retrieval file completely and compare each new block with the retrieved items one by one, then mark each block ok, edited or reverted. The fact lane publishes facts, sources, relations and processed entries after check-facts; the knowledge lane serially publishes checked knowledge in batch order and may overlap the next fact batch. Knowledge failure preserves committed facts and the failed stage's durable continuation; displayed progress advances only after both lanes finish. Reverted blocks never publish. Knowledge changes create or update; unresolved archive or merge cases become stale flags for the Dreamer. A failed stage resumes with earlier passed stage files kept. Any stage's terminal failure counts once toward the three-failure switch-off; cancellation counts nothing. Each stage has a soft step and context-growth budget. Each persisted main-session entry checks for 10,000 pending compressed-view tokens; an import checks once at its final selected head, triggered by its newest persisted entry. Historical bootstrap at startup, session-start restore or enabling memory follows that rule only when new selected entries were persisted; fully imported resume, zero-append scans, sibling-only imports and Pi tree navigation create no check. Fact publication also rechecks N at the latest selected head without waiting for a main turn end; other ordinary completion grants no new opportunity, and busy checks accumulate no owed runs. A run processes the oldest whole-entry prefix within 10,000 tokens and the model context capacity. Thinking-only entries contribute no material or pending tokens but remain processing members and are marked processed at fact publication. Fresh material reuses compact assembly at the batch's last exact entry, with processed-Raw refill disabled and preceding facts and current visible Knowledge retained. The Noter always runs fresh: a fork's prefix is the main conversation, not the compaction memory the Noter starts from. A partly processed Turn may still have pending entries.
- **Dreaming** — incremental maintenance of visible project/global knowledge, never session scope and never to fit a budget. Candidate knowledge is changed, flagged or unscored knowledge since the last successful project run; suspected duplicate or contradictory items marked during full-pool clustering (with a level and partners) only fill spare group capacity. It is due when the Noter-changed items reach `dreaming.triggerKnowledge` or the unscored knowledge reaches `dreaming.triggerUnscoredRatio` of the temporary pool. Repository notes and clustering run in parallel; both must pass before groups curate. New facts and linked-file diffs are shared background material, not retrieval queries. Each group's curate and scoring share one conversation and publish changes, ratings, verification and coverage together. Interrupted work retains groups and marks; only uncommitted groups restart curate, including when scoring failed. N/D seats, exact current bases, cancellation fences and three-failure switch-off remain; only a finished run resets the streak.
- **Full check** — manually requested maintenance of every current project/global item visible in a project. It uses the same clustering and grouping as incremental Dreaming, with every item a candidate. Each group curates then scores every surviving result in the same conversation. Interrupted work retains clusters, marks and committed groups. It shares the incremental Dreamer's exclusive claim; neither can overlap the other. Fact back-fill and a separate verify stage are excluded.
- **Coverage** — the exact per-version, per-pool processing record (`knowledge_processed`) a committed Dreamer group writes for reviewed current versions and its resulting revisions. Refused or concurrently changed versions remain pending. A version is covered only in its owning pool. A project move leaves it uncovered in its new pool.
- **Group** — up to 50 ordered, unique candidate items, arranged by clusters of at most 10. Up to 50 candidates share one group; larger candidate sets form parts by clustering group that merge in order while they fit. Marks never open or split a group: each group's spare capacity takes marked items by level (high, medium, low), then same cluster, then same clustering group, each with its unplaced partners, and theirs in turn, as one unit. Membership, marks and shared background persist with the run. At most five groups curate concurrently. Other same-cluster items are title-only references, never mutation targets or absorbed merge parents.
- **Repository notes** — one reusable exploration result, at most 10,000 tokens, prepared with the Dreamer system prompt and the knowledge-only compact prefix. Groups receive exactly system → knowledge → notes → background material; group histories and fact bodies live in workspace files or address-readable memory, not the prefix.
- **Consolidation** — retired extraction stage. Historical C runs, costs, logs, actor labels and processing rows remain readable as C; no new worker, seat, trigger or configuration exists. Historical unconsolidated facts are neither cleared nor replayed by retirement. N owns knowledge create/update; archive, merge and split remain D-only. Manual knowledge writes allow fact-backed create/update/archive.

## Relations (annotations, never derived state)

- **Support** — a historical annotation that a newer fact affirms an older one: adoption, approval, agreement, an answer, a restatement, execution of a ruling. Refused on new facts.
- **Caused by** — a fact states an outcome caused by another visible recorded fact; at most two causal annotations per fact, only where the source states causation. It is shown like historical support, never a propagation trigger.
- **Negate** — a newer fact opposes or invalidates an older one: withdrawal, veto, found wrong, a new state overturning the old, doubt, objection, evidence that does not fit.
- **Strength** — the Noter's confidence that the relation holds: *strong* when the raw states it, *weak* when inferred or partial. Attribution comes from each source's derived role and authored segment, or the saved actor on a legacy fact, not from the strength.
- No fact is ever hidden or retired by a relation. Automatic and path-scoped collection material shows a relation only when both Fact endpoints are on the selected path. An explicit `F<n>` trace remains unrestricted and marks relations whose other endpoint is inapplicable there. Relations show N and D the recorded annotations; the reader judges their bearing on the claim.
- **Dispute** — a historical knowledge category for conflicting accounts without a ruling; rendered as open. Not a fact relation.

## Scope and attribution

- **Enrollment** — the durable enabled or disabled participation of one memory-session identity, changed by `/trace on` and `/trace off` (in Pi) for that identity alone, immediately and without a reload. Explicit intent overrides its derived default; shared forks and clones share the switch. Disable pauses future work and injection while retaining memory and unrestricted reads. There is no global participation switch.
- **Baseline** — the installation-scoped instant of the plugin's first successful initialization, retained across restarts and upgrades. Only native sessions created strictly after it default enabled; unknown or malformed creation times default disabled.
- **Session** — one host conversation. Gets an id only once an assistant reply exists. Claude Code's `/clear` ends one session and starts a new one (102), as an exit followed by a startup in the same directory.
- **Lineage cursor** — one native foreground within a memory session, persisted as `(session, lineage) → (branch, head)`. Each lineage moves independently and retains its cursor while closed; reopening adopts the same key. A session with no cursor treats all stored paths as active, while any recorded cursor makes only the recorded lineages' paths active. Fact liveness requires one complete cursor path to contain its Turn, source Turns and bound entries; membership is never assembled across sibling paths.
- **Executor** — an enabled active host runtime with independent Noting fact and knowledge slots and a Dreaming slot. On CC it serves its Claude Code process's current native session: when the process moves to another (`/clear`, an in-process `/resume`), the executor leaves the old one as on exit and attaches to the new one as at startup. Each N lane prefers its own eligible work before borrowing a closed tail. D shares one database-wide seat and processes the pools visible at the executor's node, never a borrowed closed-session task.
- **Closed-session scope** — the Noting borrowing policy: off leaves tails pending, project allows the same project (default), and global allows any project. Borrowing selects only retained active lineage cursor paths (including ancestors up to each exact head); abandoned siblings stay pending until reactivated. A session without cursors retains all-path compatibility, while an invalid cursor fails the borrowed scan. The executor must be enabled and open. This policy does not change current-session work, manual catchup or Dreaming.
- **Target** — the memory session and branch whose evidence a worker processes. Its project, costs, commits, progress and deliveries remain its own even when another executor hosts the worker.
- **Claim** — exclusive ownership of one target's phase and lane across branches and executors, identified by an executor, a token and a thirty-minute expiry. Noting permits one fact owner and one knowledge owner per session; Dreaming has no second lane. Current ownership fences commits; reopening immediately replaces another executor's token. An unexpired Dreaming claim also occupies the database's sole Dreamer seat. Cancellation closes the task's tools and workspaces immediately (the cancellation fence) and expires the claim at once; a late write or pass end changes nothing. Token, expiry, takeover and project checks remain required.
- **Closed** — a session marked by normal shutdown and cleared on restore. For CC, every native SessionEnd, `/clear`'s included (102), closes its bound lineage without requiring executor termination or complete tail import; the core session stays open while another lineage is live (sessions linked on `/clear` before 102). A stale native process cannot close a reopened session. MCP executor shutdown alone, a crash or an expired claim does not establish closure.
- **Project** — the unit that shares knowledge. Shared membership comes from an explicit user command (`/trace project <name>` in Pi, `trace project <name>` in CC) or, for a new session, from its directory: the session records its repository root (the parent of git's common dir, so worktrees share it) or the real path of cwd, and joins the project that directory's recorded sessions already belong to when that is exactly one (62); none or several keep the session's own project; the home and temporary directories never key; sessions from before 62 record no directory and count for nothing; an explicit command always wins. The same name in the same database identifies the same project. Changing project ownership requires the declaring session to have no running N/D and no reached N/D trigger, including the session's Dreamer overflow and summed pending. Refusal starts no work and queues no declaration. Other sessions do not block the move; their in-flight writes still face ordinary authority checks. Moved-in project revisions become pending again in the destination, including on a return move, by clearing only their destination processing records in the relabel transaction. Order follows revision creation, not move time. Unrelated destination records and global/session processing records stay unchanged.
- **Scope** of a knowledge item — `session` (holds only in that session), `project`, or `global` (about the user, the environment, general working method).
- **Knowledge base policy** — one transactional database row (`knowledge_base_policy.base_tokens`, default 20k) that injection and compaction read as the Knowledge base. It decides no Dreamer trigger, success or archive. Settings shows it as one "Knowledge base" row and edits the database, not Pi files. The older Global/Project/Session pool budgets (`knowledge_budget_policy`) stay in their table, unread; the base starts as their sum.
- **Manual catchup** — `/trace catchup`'s finite, explicit Noting drain of the current enabled session's selected branch: bounded subagent batches below the normal Noting trigger, within a frozen entry-id boundary. Start and successful complete-batch checkpoints check N/D; fact publication checks N only. N has one seat per lane per session and D one database-wide seat. Busy work is not queued or adopted. Completion requires an exhausted frozen Raw backlog, all admitted knowledge batches finished, no due D, and no owned work still running; below-threshold knowledge may remain. Empty or dropped results do not re-arm the loop. A failed Noting step immediately retries the same lane under its existing boundary, without checking the other phase; a failed Dreaming run does not (it retries at the next entry-end check) and ends the drain for the same session and path, whoever started the run; ordinary logical-task failure accounting turns memory off after three consecutive failures and ends the drain. Cancellation ends the drain. Stop/off/shutdown/path changes fence further launches. Later Raw never extends the frozen boundary.
- **Stop** — `/trace stop`'s cancellation of one executor's background work (its own manual catchup plus any ordinary or borrowed work), reusing the same claim, token-fence and cancellation machinery as shutdown. It never disables enrollment, never edits configuration and never touches another executor's claim.

## Reading

- **Foreground Knowledge delivery** — current visible exact versions minus the delivered state recorded in the per-node delivery records on the selected path: the latest compaction's baseline plus later deliveries (97). Facts and Raw never substitute for a Knowledge body. Pi may publish one Knowledge-only hidden message at its ordinary prompt entry; CC publishes at startup/resume/clear, in its own compaction of a main-session manual or automatic compaction through the function hook (after the native one when that compaction is not built), and at UserPromptSubmit for missing-body recovery; SessionStart(compact) does not inject. State notices are separate, tagless and reveal no reader-invisible successor. The Knowledge base charges accumulated base cost, and the body/pointer pools charge their own accumulated `temporary_tokens`/`pointer_tokens`; every delivery counts, including repeats. A version delivered as a title only is recorded as such and does not hide a later body. A publication is delivered when emitted: every part of a successfully staged publication counts, including a part Claude Code persisted to a file. Transcript carriers are not read back. Budget omissions and failed staging establish no delivery.
- **Injection** — the same Knowledge renderer and exact-version foreground predicate; compaction separately carries knowledge, recent facts, and pending compressed Raw views. Knowledge is grouped by category in glossary order (`constraint`, `understanding`, `goal`, `open`, `reference`; legacy `mechanism` and `term` render in `understanding`, `dispute` in `open`), each group opened by a `## <category> (<n>)` line and omitted when empty, each item retaining its category label, items inside a group ordered by last change, oldest to newest (132). A common header explains this, that position does not compare items across categories, and that a later claim on the same object within a category stands until merged; selection is by score (see Score), not by age. CC SessionStart stages one immutable 24-slot snapshot, keyed on the event, for Hooks starting within its producer's original 55-second window; database commits do not invalidate eligible readers. A later invocation outside that window renders afresh. Staging records the delivery (97). Within that snapshot, knowledge is packed in that category-then-oldest order with next-fit, never backfilling earlier segments; a group may continue into the next segment, and each segment's block groups and counts its own items; global order is the existing segment number followed by position within the segment, not native arrival order. Facts and Raw may fill gaps. Every capacity check prices the final grouped carrier, headers included. Repeated domain framing, state notices and receipts count against their owning cap. The slicer trims in core's selection order with base/body/pointer caps kept apart; slice headers record base (`t`), body (`u`), pointer (`v`) charges and title-only versions (`i`). Host JSON framing remains separately bounded. Budget reduction removes the lowest-ranked optional items of the overfull pool before state notices without backfilling earlier segments.
- **Score** — a Knowledge item's importance, 1–100, stored with three integer ratings (consequence, frequency, current), each 1–5. The score is the geometric mean of the ratings mapped from 1–5 onto 1–100; consequence 5 imposes a floor of 81. Ratings belong to an exact resulting version and publish with that group's curate changes; incremental scoring targets unscored surviving versions, while full check rates every survivor. Scoring receives each target's label, title, category, scope and resulting body without anchors or curate accuracy, retaining the curate conversation's knowledge and readable evidence. Scores are otherwise hidden from agent input. The Knowledge base takes scored items whole in score order, ties newer version first; the first scored item that does not fit stops the base and the rest become titles (user ruling, 2026-10-22). A changed item retains its prior score and ratings until new scoring commits.
- **Compaction** — replacement of the context with the injection block. The core allocator renders one frozen path snapshot without a model and reports pending Raw omissions. A host uses the custom replacement only when every pending Raw entry fits the Raw base plus temporary allowance; otherwise it compacts natively (133 R1). Unexpected host-caught errors, including live-task lookup errors, also leave compaction to the host. Omitted Raw stays pending; compaction starts no extraction worker. Pi and Claude Code main-session manual and automatic compactions use this policy when the hooks are loaded (102); a plugin's, a precomputed or a subagent's compaction stays Claude Code's own. A `/compact` with instructions (non-empty after trimming) stays native on both hosts (130). Claude Code then appends the Knowledge supplement; Pi recovers Knowledge through ordinary delivery at the next prompt. A custom replacement keeps no original message: the turn in flight is its newest Raw.
- **Material window** — Knowledge, facts and Raw retain independent 20k/10k/10k bases. The one temporary pool adds 10k (182), making a 50k envelope before the fixed reading guide and live tasks. Already-noted Raw and full facts stay inside their bases. Framing and receipts count in their owning budgets; bases and the pool never lend to one another.
- **Temporary pool** — one pool (`compaction.temporaryTokens`, default 10k; 182) fills in this order, later classes dropping first: pending Raw overflow (compaction only); whole unscored Knowledge newest first, an unscored item that does not fit being listed as a title instead; titles of all Knowledge not shown whole (unscored fallbacks first, then score descending, ties newest first); then human user entries and uncovered fact titles together by newest path turn (140). Each turn's users precede its titles; the first misfit stops both kinds. Reaches remain `compaction.userTurns`/`compaction.titleTurns` (100 each), anchor-inclusive; users are middle-cut at `compaction.userEntryTokens` (300). Titles/excerpts grant no body coverage; delivered knowledge titles are not repeated but can later upgrade to bodies. A compaction, `/clear` or session start begins a fresh pool; each delivery records its charge, and ordinary prompts spend only the pool's remainder. Noter shares the allocator at its batch endpoint; its frozen Raw batch needs no overflow. Capacity negotiation trims the pool, then full historical facts. Live running tasks remain outside all budgets.
- **Refill** — superseded by the single allocation under Material window (73): already-processed Raw fills only its own base remainder after pending Raw; this refill is disabled only for Noting's exact pending batch. Facts fill their own window regardless of historical processing. A fact is excluded only when its nonempty complete source-entry binding is fully covered by the final Raw span or retained originals/recognized bounded carriers; this applies to unconsolidated facts too, which stay pending in the store. Complete bindings not wholly covered by Raw stay eligible; missing bindings or inconsistent stored segments are data corruption, not a coverage fallback. A discarded summary proves no retained coverage. Omitted items start no work, reset no processing and claim no supplied IDs.
- **Memory material coverage invariant** — withdrawn by 73: bounded material is not semantic losslessness, and an ID or omission receipt is not a body. The core trace view may truncate Raw and facts with receipts without changing processing. Under 133 R1, an actual host compaction delegates to native when pending Raw would be omitted; that Raw remains pending for Noting.
- **Compaction boundary** — the last compaction the host successfully persisted on the selected ancestry. A request to compact, a failed or cancelled attempt and a compaction on a sibling path are not one. A Noter whose frozen material entries include any entry before it runs with fresh context for the whole batch; thinking-only processing members do not decide this.
- **Trace** — the internal address renderer and human audit API, not a model-callable tool. Models read memory through `trace://`; event ranges, comma lists and old trace-address path fallback are removed. Internal historical source parsing and stored citations remain unchanged.
- **Search** — lexical lookup over knowledge (every version, marked current, superseded or archived), facts and Raw, one line per hit; a Raw hit's text is the exact Read of its address. `code` runs a script over the structured hits in a sandbox, and an output past the cap is saved to a file the caller's own Read can open, in every host and worker. No hit does not mean absent.
- **Memory files** — memory read at `trace://` addresses, a read-only virtual namespace. Exact node views use `trace://<layer>/S<n>[/T<t>]`: `knowledge` is a fresh context's knowledge, `compact` is manual compaction material without a continue sentence, `facts` contains Turn contributions and uncovered-entry paths, and `raw` is the compressed overview. Only raw accepts `#E<k>` (requires T, whole entry) and `@user`, `@assistant` or `@observation` (role check). Omitted T uses the current selected head; explicit T prefers that containing branch, otherwise the containing source path with greatest HWM entry id then path id. `trace://S<n>` lists one Turn per line with its facts/raw paths. K/F/version/history views and root knowledge identity lists remain. Recursive Grep searches facts and whole Raw leaves, never overview duplicates or knowledge/compact injections; knowledge-all still searches all immutable versions. Reading records no delivery or state. Ordinary Read and Grep use each host's limits; a continuation reads the same `trace://` path with offset/limit and renders again, like an ordinary file that may change between calls. Rendered backing paths are not exposed to the model. Session knowledge and compaction views return whole; Pi delegates ordinary reads through native operations. One shared reading guide, at most 200 estimated tokens, appears once per injection/material; root lists the session-list entries without expanding the guide. Writes under `trace://` are refused.
- **Retrieval policy** — the text saying when to look memory up (only when the answer would change the next step), apart from the reading guide, which teaches format. Each run sees it once, in its system prompt (a Claude Code main session through the plugin's `prompt.compose` hook, only with function hooks loaded and memory on); a fresh worker (N or D) gets it too. With the guide it stays within 500 estimated tokens.
- **Global preference** — one of the defaults the Pi menu's Settings entry saves under `trace-memory` in the resolved agent settings file: N/D models and subagent thinking levels, and the closed-session scope that decides whose finished sessions this executor may work on. They are the existing canonical configuration keys, not a second system; a project or environment layer still overrides them, and a saved value reaches tasks admitted afterwards while running tasks keep the model, thinking level and scope frozen with them. Database Knowledge budgets appear in the same Settings screen but are not global preferences and never write that file.

## Process

- **Logical task** — one target session, phase and stable backlog key: the oldest selected source entry for Noting, none for the Dreamer, whose task is its session. An automatic failure can retry only at a later entry end; manual catchup retains its immediate same-phase retry for the Noter only. Three terminal business failures of the same Noting task make the session dormant; success resets that task and explicit on resets every target streak. Reopen does not reset it. Cancellation is not a business failure. A Dreamer run that does not finish normally counts once like a Noter run and retries at the next entry end with its operation count kept; three in a row make it dormant, and only a finished run resets that streak (146).
- **Disposition** — what a model's file asked of one knowledge item and what became of it: an operation applied, or refused as stale and left for the next run. A timeout is not a completed maintenance pass. Historical Dreamer skips and Consolidation skipped-fact reasons remain in old run audits.
- **NEAR** — historical Noter lexical-review audit only. New Noting has no similarity scan, feedback or mandatory relation review; old audit records remain readable.
- **Subagent** — fresh-context execution: the run happens in a private child prepared from the frozen material alone. The only execution mode of N and D.
- **Material** — the frozen parts one memory run works from: the active knowledge, the historical facts, the compressed Raw views of its selected entries, its own range and the budget receipts. Noting reuses that exact prefix when knowledge starts within its reuse window; a delayed knowledge start freezes only the original Knowledge and that batch's committed facts, without Raw or historical facts.
- **Run record** — an audit record for noting, consolidation, dreaming or manual work holding the exact input sent to the model, the prompt version, the model, the execution mode, and the output. Knowledge revisions point at the run that produced them.
- **Worker log** — the child session's own JSONL, written by the host itself, named in the run record as `nativeLog`. On Pi it is by default a direct child of the agent's `sessions/trace-memory` directory — one level under Pi's session root, where external daily-cost readers look, and where Pi's all-session browser lists it. On CC it is the worker's native Claude Code session, one directory under Claude Code's own `projects` root, named for the run's real cwd (its workspace for workspace-bearing tasks) — where claude-powerline's daily cost counts it like any other session. Neither host moves logs written under an earlier layout.
- **Completion level** — the prefix on an event fact: completed (result evidence visible), reported (claimed only), dispatched, attempted.
- **Writer schema** — the foreground `note` and `memory` tools write one fact or one knowledge operation at once. The Noter does not use them: it writes files.
- **Local handle** — `$n`, the position of a fact in a manual or workspace write; a workspace file names its facts by label (`f1`). Fact publication durably binds labels to F IDs for relations and the later knowledge lane's `supports`, never by rewriting prose.
- **Commit durability** — the database trades some crash safety for a responsive event loop: an OS crash or power loss can roll back the most recently committed transactions (a few seconds of Raw, facts or knowledge); a process crash alone loses nothing already committed. Recovery needs no operator step: on restart, each host re-imports any Raw missing from the database out of its own native transcript or session, and Noting/Dreaming work whose commit was rolled back is pending again, exactly as if it had never run. A rolled-back run's spend record is lost with it.

## Languages

Memory content is written in the language of the conversation. Everything that is work — code, comments, docs, prompts, subagent briefs — is English.
