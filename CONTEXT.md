# Trace Memory — domain glossary

Terms only. No implementation detail. When a term here conflicts with usage in code or prompts, this file wins and the other side is fixed.

## Layers

- **Raw** — the conversation as the host recorded it: user messages, tool calls with results, assistant text. The only source of truth. Never edited.
- **Source entry** — one completed native conversation message: user text, assistant content with tool calls, or a tool result. Identity is its native id within the session lineage, never its text. It belongs to a Turn and receives an immutable Turn-local E ordinal; branch gaps never renumber it. The host normalizes ordered content blocks once for rendering and exact citation validation. Plugin injections and summaries are never sources.
- **Compressed Raw view** — the shared, bounded head/tail excerpt of one source entry, in Pi's compaction line shape with stable entry/block addresses (`[T<n>#E<m>@text] user: …`, `[T<n>#E<m>@<callId>] <tool>(<key>=<JSON>)`, `[T<n>#E<r>@<callId>] <tool> <status>: …`) and honest omission counts in one marker family (`[... N characters truncated]`). One view everywhere, under one profile of three independent budgets: `E` for the whole entry, `C` for each tool-call part, `R` for each tool-result part, each including the labels, syntax and markers inside it. A marked compressed view is visible Raw whether or not it was truncated. The original Raw remains available through full trace, uncompressed under the same labels, with lossless cursor pagination (default 2,000 estimated tokens per page).
- **Turn** — one user message and everything it triggered until the next user message. A compaction is also recorded as a turn, with no facts.
- **Fact** — one claim extracted from a turn that can be overturned on its own. Six categories: question, proposal, decision, observation, interpretation, event. Carries an actor (user or agent), a source address, optional verbatim quote, and relations.
- **Fact group** — the display of selected facts under their owning Turn: Turns in chronological start-time order, facts in ascending F-id order. A group need not cover its entire Turn; grouping changes neither citation scope nor processing membership, and all original source references stay on each fact.
- **Knowledge** — one durable, decontextualized conclusion consolidated from facts. Seven categories: constraint, open, dispute, goal, mechanism, term, reference. Each immutable revision stores the complete resulting body (or archival state) and exact lineage.
- **Supports** — the facts directly grounding one revision. A revision applies when its own scope admits the reader and every direct support belongs to the revision's scope and to its fact owner's current foreground. Lineage is provenance, not a recursive applicability condition. Evidence-driven changes store exactly their submitted supports. When a trusted Dreamer submits an empty list, core materializes the exact parents' supports at commit: one parent's set for update/archive/split and the union of both sets for merge. Migration fills historical empty sets in parent-before-child order; a revision stays empty only when its entire ancestry is empty.
- **Knowledge lineage** — immutable revision history: creation has no parent; update/archive have one; merge has exactly two distinct-identity parents and one result, with the older Knowledge identity as survivor; split has one parent and atomically creates exactly two new Knowledge identities. Effective resolution is stateless: among branches whose revisions' direct facts currently apply, the later committed conflicting branch has priority; an earlier branch returns when the later branch stops applying. The same resolved graph supplies reads and atomic stale-base write checks, so consumers never expose an effective fork. Archives participate before body filtering. Parent and merge/split links preserve provenance without inheriting applicability.
- **Trigger origin** — the target memory-session identity plus the immutable ordered `source_entries.id` sequence through the triggering entry, frozen for execution and run audit. Later foreground navigation does not move it; historical absence stays unknown. Origin is provenance, not knowledge validity or permission to write a stale base.
- **Reason** — the commit message of one knowledge commit: what changed and why it was chosen. It is not a durable claim and has no authority of its own; it establishes no evidence, scope, applicability, accounting coverage or completion level, and addresses written in it are never read as citations.
- **Topic** — a subject label on one knowledge revision: the module, component or domain the conclusion is about, beside its category. Labels are free strings, trimmed, deduplicated and versioned with the revision that carries them; several may apply and none is required. Classification only — a topic changes no scope, evidence permission, lifecycle or eligibility, and sharing one merges no knowledge.
- **Noting** — the phase in which the Noter turns raw into facts. Each eligible entry completion checks for 10,000 pending compressed-view tokens; a run processes the oldest whole-entry prefix within 10,000 tokens and the model context capacity. A partly processed Turn may still have pending entries.
- **Dreaming** — bounded fresh-subagent update/binary-merge/binary-split/archive maintenance of one due Knowledge pool. Every live ingested entry checks each applicable pool independently (new selected history in CC bootstrap checks the complete final path once; restart/restore with no appended entries grants no opportunity): current visible, non-archived versions without a processing record in that pool count once at their full rendered size. A pool is due at half its budget or when over budget; its frozen range fits its full budget. Current reference knowledge and the range share the Knowledge window plus shared allowance; direct facts have a separate 10k cap. Exact reads, current visible bases, pool authority and the live claim fence guard immediate atomic writes. On success or failure, terminal processing records the frozen range and own revisions; cancellation before the first commit records nothing. Ranges are not retried, and own outputs do not trigger themselves. Budget excess alone is not failure; unchanged residual excess does not re-trigger until pool growth, a budget change or new pending material. Partial writes survive later failure.
- **Consolidation** — the phase in which the Consolidator creates knowledge from facts; it cannot update, merge, split or archive. Its first valid submission commits without a review round. A changed claim creates a new item; Dreamer later reconciles the identities. Each eligible entry checks for 5,000 rendered tokens of applicable unconsolidated facts and takes an oldest-first whole-fact prefix within 10,000 tokens. Manual knowledge writes allow fact-backed create and archive only. Outside explicit manual catchup, worker completion starts no phase; shutdown and tree switching never do.

## Relations (annotations, never derived state)

- **Support** — a newer fact affirms an older one: adoption, approval, agreement, an answer, a restatement, execution of a ruling.
- **Negate** — a newer fact opposes or invalidates an older one: withdrawal, veto, found wrong, a new state overturning the old, doubt, objection, evidence that does not fit.
- **Strength** — the Noter's confidence that the relation holds: *strong* when the raw states it, *weak* when inferred or partial. Who acted is carried by the fact's category and actor, not by the strength.
- No fact is ever hidden or retired by a relation. Automatic and path-scoped collection material shows a relation only when both Fact endpoints are on the selected path. An explicit `F<n>` trace remains unrestricted and marks relations whose other endpoint is inapplicable there. Relations show the Consolidator the shape; the Consolidator judges.
- **Dispute** — the Consolidator's judgment that two accounts of the same object under the same conditions coexist without a ruling. A category of knowledge, not a relation.

## Scope and attribution

- **Enrollment** — the durable enabled or disabled participation of one memory-session identity, changed by `/trace on` and `/trace off` (in Pi) for that identity alone, immediately and without a reload. Explicit intent overrides its derived default; shared forks and clones share the switch. Disable pauses future work and injection while retaining memory and unrestricted reads. There is no global participation switch.
- **Baseline** — the installation-scoped instant of the plugin's first successful initialization, retained across restarts and upgrades. Only native sessions created strictly after it default enabled; unknown or malformed creation times default disabled.
- **Session** — one host conversation. Gets an id only once an assistant reply exists.
- **Lineage cursor** — one native foreground within a memory session, persisted as `(session, lineage) → (branch, head)`. Each lineage moves independently and retains its cursor while closed; reopening adopts the same key. A session with no cursor treats all stored paths as active, while any recorded cursor makes only the recorded lineages' paths active. Fact liveness requires one complete cursor path to contain its Turn, source Turns and bound entries; membership is never assembled across sibling paths.
- **Executor** — an enabled active host runtime with one slot per phase. Noting and Consolidation can overlap and prefer their own eligible work before borrowing a closed tail. Dreaming shares one database-wide seat and processes a due pool visible at the executor's node, never a borrowed closed-session task.
- **Closed-session scope** — the Noting/Consolidation borrowing policy: off leaves tails pending, project allows the same project (default), and global allows any project. The executor must be enabled and open. This policy does not change current-session work, manual catchup or Dreaming.
- **Target** — the memory session and branch whose evidence a worker processes. Its project, costs, commits, progress and deliveries remain its own even when another executor hosts the worker.
- **Claim** — exclusive ownership of one target's phase across branches and executors, identified by an executor, a token and a thirty-minute expiry. Current ownership fences commits; reopening immediately replaces another executor's token. An unexpired Dreaming claim also occupies the database's sole Dreamer seat. Cancellation closes knowledge tools immediately but retains the exact claim through terminal processing; disabling the executor may not prevent that bookkeeping. Token, expiry, takeover, project and frozen-range checks remain required.
- **Closed** — a session marked by normal shutdown and cleared on restore. A crash or expired claim does not establish closure; an unclosed crashed conversation waits for resume.
- **Project** — the unit that shares knowledge. Shared membership comes from an explicit user command (`/trace project <name>` in Pi, `trace project <name>` in CC) or, for a new session, from its directory: the session records its repository root (the parent of git's common dir, so worktrees share it) or the real path of cwd, and joins the project that directory's recorded sessions already belong to when that is exactly one (62); none or several keep the session's own project; the home and temporary directories never key; sessions from before 62 record no directory and count for nothing; an explicit command always wins. The same name in the same database identifies the same project. Declaration preserves the selected-path Noting/Consolidation backlog and live-claim guards. Dreaming being due or an inactive range being open does not block it; an active Dreamer whose session belongs to an affected project or whose range touches an affected pool does. Moved project revisions become pending only where the destination pool has no record for that version; moving back to a pool that already handled it adds no work. Global/session processing records stay unchanged.
- **Scope** of a knowledge item — `session` (holds only in that session), `project`, or `global` (about the user, the environment, general working method).
- **Knowledge budget policy** — one transactional database row with Global/Project/Session pool budgets, defaulting to 4k/15k/1k. Pools measure current visible non-archived versions, regardless of processing records. Their safe-integer sum supplies the 20k Knowledge base window; half each pool budget is its Dreamer trigger. A budget is a maintenance trigger, not a write gate. Settings edits the database, not Pi files. Migration upgrades an unchanged old-default 4k/10k/1k row; any other stored policy is retained and reported.
- **Manual catchup** — `/trace catchup`'s finite, explicit Noting drain of the current enabled session's selected branch: bounded subagent batches below the normal Noting trigger, within a frozen entry-id boundary. Each successful Noting completion checks Consolidation's ordinary trigger; each successful catchup-launched Consolidation completion checks Dreaming's ordinary trigger, including after the last Noting batch. Noting and Consolidation can overlap, with one seat each per session; Dreaming has one database-wide seat. A busy trigger is discarded, not queued or replayed on release. Consolidation and Dreaming are not drains, Dreamer completion starts no work, and completion need not leave zero pending facts or knowledge. Stop/off/shutdown/path changes fence further launches. This is the sole completion-chaining exception; later Raw never extends its frozen boundary.
- **Stop** — `/trace stop`'s cancellation of one executor's background work (its own manual catchup plus any ordinary or borrowed work), reusing the same claim, token-fence and cancellation machinery as shutdown. It never disables enrollment, never edits configuration and never touches another executor's claim.

## Reading

- **Foreground Knowledge delivery** — before every enabled ordinary prompt, the host may publish one Knowledge-only hidden message. The core selects applicable current exact revisions not already visible at that version, suppresses only changes whose nonempty direct supports are all visible as Facts or are all proven to bind to retained original/bounded Raw entries, and emits applicable archive/supersede/merge/split notices separately from bodies. The Knowledge base plus derived shared allowance (45k by default) charges retained applicable Knowledge bodies and state notices first; candidates then fit as whole rendered items. No Fact, Raw, omission-only, initial-only, command-generation, or processed-status material is published.
- **Injection** — the same Knowledge renderer and evidence-aware foreground predicate, used by every ordinary prompt; compaction separately carries knowledge, recent facts, and pending compressed Raw views. Knowledge retains category groups and chronological display within each group. A common header explains that larger commit numbers are newer and newer claims on the same object stand until merged; budget selection drops the oldest optional items first.
- **Compaction** — replacement of the context with the injection block. Over a frozen snapshot of the path it has two outcomes: a custom replacement, or a request that the host's own native compaction take over. The core allocator calls no model. Host-managed bounded recovery may run model-backed memory tasks before either outcome; native delegation additionally uses the host's own summarizer.
- **Compaction recovery** — one bounded operation when required facts, Raw or Knowledge state notices exceed their bases plus the shared allowance. Each useful phase can run at most once, subject to ordinary eligibility; independent phases may overlap. Reuse waits only for a compatible running task, never retries a completed Dreamer range. Reallocation reads actual committed progress; final publication rechecks path and project binding. Remaining required excess delegates to native compaction. User cancellation starts no native compaction.
- **Material window** — a compaction part: Knowledge has a database-derived 20k base and facts/Raw have 10k bases each. The shared allowance is derived at runtime by summing the three pool triggers and the Noting/Consolidation triggers: 25k at defaults, with no separate setting or stored value. Reserve required pending Raw, unconsolidated facts and Knowledge state notices first; allocate the remaining shared capacity to Knowledge, historical Raw, then historical facts. Bases never lend to one another. Knowledge bodies are optional current-version material, not protected pending work. Framing and receipts are charged once. The default maximum envelope is 65k; Consolidator Knowledge can use base plus shared allowance independently of its 10k fact/range budget.
- **Refill** — optional history within its base remainder plus the remaining shared allowance: newest already-extracted Raw first, displayed in source order, then newest already-consolidated facts, displayed in chronological Turn groups. A fact is excluded only when its nonempty complete source-entry binding is fully covered by the final Raw set: retained originals/recognized bounded carriers, required pending Raw and selected history. Unknown, incomplete or partly uncovered bindings stay eligible; required facts are never excluded. A discarded summary proves no retained coverage. Filtering precedes budgeting; omitted items start no work, reset no processing and claim no supplied IDs.
- **Memory material coverage invariant** — a successful custom compaction preserves every selected-path bounded Raw view awaiting Noting and every complete fact awaiting Consolidation. Current knowledge and historical supplements may be omitted within their windows. A knowledge processing record grants no special protection. Native compaction is the accepted lossy fallback; an ID or omission receipt is not a body, and bounded Raw is not semantic losslessness.
- **Compaction boundary** — the last compaction the host successfully persisted on the selected ancestry. A request to compact, a failed or cancelled attempt and a compaction on a sibling path are not one. A Noter whose frozen entries include any entry before it runs with fresh context for the whole batch.
- **Trace** — the tool that walks addresses: knowledge → its facts → the source turn; knowledge revisions (`K7@2`, `K7@2..4`); a fact's later strong negations (`F101..`). Also the project name.
- **Search** — lexical lookup over facts and knowledge (and optionally a session's raw) returning addresses. No hit does not mean absent.
- **Global preference** — one of the defaults the Pi menu's Settings entry saves under `trace-memory` in the resolved agent settings file: Noter and Consolidator execution modes, each phase's model and subagent thinking level (Dreamer is always a fresh subagent), and the closed-session scope that decides whose finished sessions this executor may work on. They are the existing canonical configuration keys, not a second system; a project or environment layer still overrides them, and a saved value reaches tasks admitted afterwards while running tasks keep the mode, model, thinking level and scope frozen with them. Database Knowledge budgets appear in the same Settings screen but are not global preferences and never write that file.

## Process

- **Logical task** — one target session, phase and stable oldest selected backlog item: a source entry for Noting, a fact for Consolidation, or the frozen pool range's first revision for Dreamer. Three terminal business failures of the same task disable memory; success resets that task and explicit on resets every target streak. Reopen does not reset it. Cancellation is not a business failure. Dreamer ranges end once and are not retried; residual budget excess is not failure.
- **Disposition** — an operation or reasoned skip recorded by a model. Dreamer dispositions can be evaluated separately from terminal processing: automatic range consumption is not proof that every item was deliberated. Consolidation retains explicit skipped-fact reasons but has no second-round accounting check.
- **NEAR** — the Noter's lexical review of candidate facts against earlier same-path facts. Similarity alone establishes no relation. Consolidation has no corresponding second round.
- **Fork** — inherited-context execution: the run happens in a child of the conversation itself, continuing from its persisted state. The execution mode, never the evidence path called branch. Runs recorded before this name existed carry the old spelling and are read as legacy request-copy execution.
- **Subagent** — fresh-context execution: the run happens in a private child prepared from the frozen material alone. The alternative to fork.
- **Material** — the frozen parts one memory run works from: the active knowledge, the historical facts, the compressed Raw views of its selected entries, its own range and the budget receipts. A task freezes it once; both execution modes read that one.
- **Increment** — what an inherited-context run adds to a conversation that already carries the raw, the delivered facts and the injected knowledge: its instruction, the range, and the head reply and source index, or the exact fact list. Never a second copy of the material.
- **Run record** — an audit record for noting, consolidation, dreaming or manual work holding the exact input sent to the model, the prompt version, the model, the execution mode, and the output. Knowledge revisions point at the run that produced them.
- **Worker log** — the child session's own JSONL, written by Pi, named in the run record as `nativeLog`. By default it is a direct child of the agent's `sessions/trace-memory` directory — one level under Pi's session root, where external daily-cost readers look, and where Pi's all-session browser lists it. Logs written under an earlier default stay at their original paths.
- **Completion level** — the prefix on an event fact: completed (result evidence visible), reported (claimed only), dispatched, attempted.
- **Local handle** — `$n`, the n-th fact of the current noting batch, used for in-batch relations before ids exist; the writer resolves it.

## Languages

Memory content is written in the language of the conversation. Everything that is work — code, comments, docs, prompts, subagent briefs — is English.
