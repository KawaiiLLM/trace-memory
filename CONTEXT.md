# Trace Memory — domain glossary

Terms only. No implementation detail. When a term here conflicts with usage in code or prompts, this file wins and the other side is fixed.

## Layers

- **Raw** — the conversation as the host recorded it: user messages, tool calls with results, assistant text. The only source of truth. Never edited.
- **Source entry** — one completed native conversation message: user text, assistant content with tool calls, or a tool result. Identity is its native id within the session lineage, never its text. It belongs to a Turn and receives an immutable Turn-local E ordinal; branch gaps never renumber it. The host normalizes ordered content blocks once for rendering and exact citation validation. Plugin injections and summaries are never sources.
- **Compressed Raw view** — the shared, bounded head/tail excerpt of one source entry, in Pi's compaction line shape with stable whole-entry addresses with role filters (`[T<n>#E<m>@user] user: …`, `[T<n>#E<m>@assistant] <tool>(<key>=<JSON>)`, `[T<n>#E<r>@observation] <tool> <status>: …`) and honest omission counts in one marker family (`[... N characters truncated]`). One view everywhere, under one profile of three independent budgets: `E` for the whole entry, `C` for each tool-call part, `R` for each tool-result part, each including the labels, syntax and markers inside it. A marked compressed view is visible Raw whether or not it was truncated. The original Raw remains available through full trace, uncompressed under the same labels, with lossless cursor pagination (default 2,000 estimated tokens per page).
- **Turn** — one user message and everything it triggered until the next user message. A compaction is also recorded as a turn, with no facts.
- **Fact** — one topic's titled slice over a continuous stretch of conversation, restoring the episode rather than a decontextualized conclusion. A slice may span Turns and retains its question, reasoning, evidence and revision together. Each contributing whole entry has one authored segment; core orders segments by the selected source path, joins their text into the body and derives each source's role (user, assistant, observation). The earliest source Turn owns a new fact. Its title identifies the episode; assistant prose names the original harness. Optional support/negate relations remain annotations. Legacy bodies, sources, category, actor, status and quote are unchanged. N's 1,000-token cap applies to the body, not the title or citations; material windows charge the complete rendering. Manual writes commit immediately.
- **Fact group** — automatic material displays selected complete facts under their owning Turn: Turns in chronological start-time order, facts in ascending F-id order. A group need not cover its entire Turn. A direct Turn read instead shows each fact with a contribution there, restricted to that Turn's segments; a legacy fact without segments is shown whole. Neither view changes ownership, citation scope or processing membership.
- **Knowledge** — one topic's continuing understanding grounded in facts, retaining enough background, reasons, evidence strength and retrieval context to be understood outside the original discussion. Granularity follows importance, joint maintainability and budget, not object count or category differences. New writes use five categories: constraint, understanding, goal, open, reference. Legacy mechanism/term group under understanding and dispute under open without rewriting stored revisions. Each immutable revision stores the complete resulting body (or archival state) and exact lineage. Noter- and Dreamer-written text is limited to 1,000 estimated tokens per result, including each split child; manual writes are unchanged.
- **Supports** — the facts directly grounding one revision. A revision applies when its own scope admits the reader and every direct support belongs to the revision's scope and to its fact owner's current foreground. Lineage is provenance, not a recursive applicability condition. Evidence-driven changes store exactly their submitted supports. When a trusted Dreamer submits an empty list, core materializes the exact parents' supports at commit: one parent's set for update/archive/split and the union of both sets for merge. Migration fills historical empty sets in parent-before-child order; a revision stays empty only when its entire ancestry is empty.
- **Knowledge version address** — bare `K12` selects current; `K12#qfzt` matches an exact immutable version and is required for mutation bases. Per-identity `K12@v3` ordinals include all branches and never renumber with scope. Complete model bodies carry tags, continued bodies only after their final fragment; previews, notices, diffs and body-free receipts carry no tag. Reads hold no grant ledger. Human audit, database keys and actual-delivery carriers retain global commits.
- **Knowledge lineage** — immutable revision history: creation has no parent; update/archive have one; merge has exactly two distinct-identity parents and one result, with the older Knowledge identity as survivor; split has one parent and atomically creates exactly two new Knowledge identities. Effective resolution is stateless: among branches whose revisions' direct facts currently apply, the later committed conflicting branch has priority; an earlier branch returns when the later branch stops applying. The same resolved graph supplies reads and atomic stale-base write checks, so consumers never expose an effective fork. Archives participate before body filtering. Parent and merge/split links preserve provenance without inheriting applicability.
- **Trigger origin** — the target memory-session identity plus one triggering `source_entries.id`, frozen for execution and run audit. An explicit trigger is used when supplied; otherwise choose the last entry on the target ancestry. Later foreground navigation does not move it; historical absence stays unknown. Existing stored multi-id origins remain unchanged and their final id is the trigger. Origin is provenance, not knowledge validity or permission to write a stale base.
- **Reason** — the commit message of one knowledge commit: what changed and why it was chosen. It is not a durable claim and has no authority of its own; it establishes no evidence, scope, applicability, accounting coverage or completion level, and addresses written in it are never read as citations.
- **Topic** — a subject label on one knowledge revision: the module, component or domain the conclusion is about, beside its category. Labels are free strings, trimmed, deduplicated and versioned with the revision that carries them; several may apply and none is required. Classification only — a topic changes no scope, evidence permission, lifecycle or eligibility, and sharing one merges no knowledge.
- **Noting** — one model run stages facts and knowledge create/update/archive in private stable slots. Both tools must be used explicitly, even for empty output. Only normal termination with all refusals resolved publishes both layers, frozen Raw progress and successful execution in one short transaction. Replacements invalidate old slot values before validation; drops never recycle handles. A valid tagged predecessor advanced by a visible effective descendant converts update to an annotated create or archive to an audited no-op, without weakening evidence or scope checks. Each main turn end checks once for 10,000 pending compressed-view tokens; ingestion and run completion grant no automatic opportunity, and busy checks accumulate no owed runs; a run processes the oldest whole-entry prefix within 10,000 tokens and the model context capacity. Fresh material reuses compact assembly at the batch's last exact entry, with processed-Raw refill disabled and preceding facts and current visible Knowledge retained. A fork inherits the parent without a Knowledge or historical-fact supplement; the host checks source coverage and Core capacity before launch. In CC, originals present only inside a compaction carrier require fresh execution, with the reason recorded for that attempt. A partly processed Turn may still have pending entries.
- **Dreaming** — bounded fresh-subagent update/binary-merge/binary-split/archive maintenance of one due Knowledge pool. Each main turn end checks the session's applicable pools together once, independently of Noting under the existing seats; importing history, busy checks and run completion accumulate no further automatic opportunities: current visible versions without a processing record in their pool are pending once, archives included (still excluded from pool size): an update weighs the amount of change since the version last confirmed in this pool, an archive weighs the removed body, and either without a confirmed baseline here counts at its full rendered size. A run is due for the session when its pools, measured as `check` measures them, exceed the Knowledge base plus the shared allowance (30k by default), or when their nonempty pending weight, summed, reaches the configured Dreamer trigger (5k by default). It writes the pool most over its own budget, else the pool with the most pending weight; another automatic run requires a later main turn end. Manual catchup retains its separate completion checkpoints. Its frozen range takes an oldest-first prefix within 10,000 completely rendered tokens, inside the total Knowledge window. No oversized oldest item bypasses that bound. The model input capacity remains a hard limit. A configurable wall-clock bound (thirty minutes by default) replaces the tool-round ceiling on both hosts. Current reference knowledge and the range share the Knowledge window plus shared allowance; direct facts have a separate 10k cap. Exact version tags, current visible bases, pool authority and the live claim fence guard immediate atomic writes. A tag matches a version, not a read history. Reasoned skips use untagged exact history addresses and need no full-body reread; they confer no mutation authority. Processing records only skipped frozen versions and own revisions, including on failure or cancellation; untouched material stays pending. Ranges end once, and own outputs do not trigger themselves. Partial writes survive later failure.
- **Consolidation** — retired extraction stage. Historical C runs, costs, logs, actor labels and processing rows remain readable as C; no new worker, seat, trigger or configuration exists. Historical unconsolidated facts are neither cleared nor replayed by retirement. N now owns knowledge create/update/archive; merge and split remain D-only. Manual knowledge writes allow fact-backed create and archive only.

## Relations (annotations, never derived state)

- **Support** — a newer fact affirms an older one: adoption, approval, agreement, an answer, a restatement, execution of a ruling.
- **Negate** — a newer fact opposes or invalidates an older one: withdrawal, veto, found wrong, a new state overturning the old, doubt, objection, evidence that does not fit.
- **Strength** — the Noter's confidence that the relation holds: *strong* when the raw states it, *weak* when inferred or partial. Attribution comes from each source's derived role and authored segment, or the saved actor on a legacy fact, not from the strength.
- No fact is ever hidden or retired by a relation. Automatic and path-scoped collection material shows a relation only when both Fact endpoints are on the selected path. An explicit `F<n>` trace remains unrestricted and marks relations whose other endpoint is inapplicable there. Relations show N and D the recorded annotations; the reader judges their bearing on the claim.
- **Dispute** — a historical knowledge category for conflicting accounts without a ruling; rendered as open. Not a fact relation.

## Scope and attribution

- **Enrollment** — the durable enabled or disabled participation of one memory-session identity, changed by `/trace on` and `/trace off` (in Pi) for that identity alone, immediately and without a reload. Explicit intent overrides its derived default; shared forks and clones share the switch. Disable pauses future work and injection while retaining memory and unrestricted reads. There is no global participation switch.
- **Baseline** — the installation-scoped instant of the plugin's first successful initialization, retained across restarts and upgrades. Only native sessions created strictly after it default enabled; unknown or malformed creation times default disabled.
- **Session** — one host conversation. Gets an id only once an assistant reply exists. Claude Code's `/clear` ends one session and starts a new one (102), as an exit followed by a startup in the same directory.
- **Lineage cursor** — one native foreground within a memory session, persisted as `(session, lineage) → (branch, head)`. Each lineage moves independently and retains its cursor while closed; reopening adopts the same key. A session with no cursor treats all stored paths as active, while any recorded cursor makes only the recorded lineages' paths active. Fact liveness requires one complete cursor path to contain its Turn, source Turns and bound entries; membership is never assembled across sibling paths.
- **Executor** — an enabled active host runtime with N and D slots only. On CC it serves its Claude Code process's current native session: when the process moves to another (`/clear`, an in-process `/resume`), the executor leaves the old one as on exit and attaches to the new one as at startup. N prefers its own eligible work before borrowing a closed tail. D shares one database-wide seat and processes a due pool visible at the executor's node, never a borrowed closed-session task.
- **Closed-session scope** — the Noting borrowing policy: off leaves tails pending, project allows the same project (default), and global allows any project. Borrowing selects only retained active lineage cursor paths (including ancestors up to each exact head); abandoned siblings stay pending until reactivated. A session without cursors retains all-path compatibility, while an invalid cursor fails the borrowed scan. The executor must be enabled and open. This policy does not change current-session work, manual catchup or Dreaming.
- **Target** — the memory session and branch whose evidence a worker processes. Its project, costs, commits, progress and deliveries remain its own even when another executor hosts the worker.
- **Claim** — exclusive ownership of one target's phase across branches and executors, identified by an executor, a token and a thirty-minute expiry. Current ownership fences commits; reopening immediately replaces another executor's token. An unexpired Dreaming claim also occupies the database's sole Dreamer seat. Cancellation closes knowledge tools immediately but retains the exact claim through terminal processing; disabling the executor may not prevent that bookkeeping. Token, expiry, takeover, project and frozen-range checks remain required.
- **Closed** — a session marked by normal shutdown and cleared on restore. For CC, every native SessionEnd, `/clear`'s included (102), closes its bound lineage without requiring executor termination or complete tail import; the core session stays open while another lineage is live (sessions linked on `/clear` before 102). A stale native process cannot close a reopened session. MCP executor shutdown alone, a crash or an expired claim does not establish closure.
- **Project** — the unit that shares knowledge. Shared membership comes from an explicit user command (`/trace project <name>` in Pi, `trace project <name>` in CC) or, for a new session, from its directory: the session records its repository root (the parent of git's common dir, so worktrees share it) or the real path of cwd, and joins the project that directory's recorded sessions already belong to when that is exactly one (62); none or several keep the session's own project; the home and temporary directories never key; sessions from before 62 record no directory and count for nothing; an explicit command always wins. The same name in the same database identifies the same project. Changing project ownership requires the declaring session to have no running N/D and no reached N/D trigger, including the session's Dreamer overflow and summed pending. Refusal starts no work and queues no declaration. Other sessions do not block the move; their in-flight writes still face ordinary authority checks. Moved-in project revisions become pending again in the destination, including on a return move, by clearing only their destination processing records in the relabel transaction. Order follows revision creation, not move time. Unrelated destination records and global/session processing records stay unchanged.
- **Scope** of a knowledge item — `session` (holds only in that session), `project`, or `global` (about the user, the environment, general working method).
- **Knowledge budget policy** — one transactional database row with Global/Project/Session pool budgets, defaulting to 4k/15k/1k. Pools measure current visible non-archived versions, regardless of processing records. Their safe-integer sum supplies the 20k Knowledge base window. A budget caps a Dreamer run and decides its success, not writes; one pool exceeding it starts no run unless the session's knowledge overflows the window. Settings edits the database, not Pi files. Migration upgrades an unchanged old-default 4k/10k/1k row; any other stored policy is retained and reported.
- **Manual catchup** — `/trace catchup`'s finite, explicit Noting drain of the current enabled session's selected branch: bounded subagent batches below the normal Noting trigger, within a frozen entry-id boundary. Start and successful completions check N/D: N drains its frozen boundary and D uses ordinary due rules. N has one seat per session and D one database-wide seat. Busy work is not queued or adopted. Completion requires an exhausted frozen Raw backlog, no due D, and no owned work still running; below-threshold knowledge may remain. Empty or dropped results do not re-arm the loop. A failed catchup step immediately retries the same phase under its existing boundary, without checking the other phase; ordinary logical-task failure accounting turns memory off after three consecutive failures and ends the drain. Cancellation ends the drain. Stop/off/shutdown/path changes fence further launches. Later Raw never extends the frozen boundary.
- **Stop** — `/trace stop`'s cancellation of one executor's background work (its own manual catchup plus any ordinary or borrowed work), reusing the same claim, token-fence and cancellation machinery as shutdown. It never disables enrollment, never edits configuration and never touches another executor's claim.

## Reading

- **Foreground Knowledge delivery** — current visible exact versions minus the delivered state recorded in the per-node delivery records on the selected path: the latest compaction's baseline plus later deliveries (97). Facts and Raw never substitute for a Knowledge body. Pi may publish one Knowledge-only hidden message at its ordinary prompt entry; CC publishes at startup/resume/clear, in its own compaction of a main-session manual or automatic compaction through the function hook (after the native one when that compaction is not built), and at UserPromptSubmit for missing-body recovery; SessionStart(compact) does not inject. State notices are separate, tagless and reveal no reader-invisible successor. The Knowledge base plus shared allowance charges the accumulated render-time cost of the deliveries recorded on the path; every delivery counts, including repeats of one version. A publication is delivered when it is emitted: every part of a successfully staged publication counts, including a part Claude Code persisted to a file. Transcript carriers are not read back. Budget omissions and failed staging establish no delivery.
- **Injection** — the same Knowledge renderer and exact-version foreground predicate; compaction separately carries knowledge, recent facts, and pending compressed Raw views. Knowledge is one oldest-first list, each item retaining its category label. A common header explains that later claims on the same object stand until merged; budget selection drops the oldest optional items first. CC SessionStart stages one immutable 24-slot snapshot, keyed on the event, for Hooks starting within its producer's original 55-second window; database commits do not invalidate eligible readers. A later invocation outside that window renders afresh. Staging records the delivery (97). Within that snapshot, knowledge is packed oldest-first with next-fit, never backfilling earlier segments; recency is the existing segment number followed by position within the segment, not native arrival order. Facts and Raw may fill gaps. Every capacity check prices the same final single-list carrier that is emitted. Final part Knowledge costs include repeated recency framing, state notices and Knowledge omission receipts; their sum must fit the remaining Knowledge allowance. Facts, Raw and the separately bounded host envelope are excluded. Budget reduction removes oldest optional bodies before state notices without backfilling earlier segments.
- **Compaction** — replacement of the context with the injection block. Over a frozen snapshot of the path it has one outcome: a custom replacement that fits its windows, truncating unprocessed material rather than delegating (73). The core allocator calls no model and never asks for the host's native compaction for capacity; only an unexpected host-caught error leaves native compaction to the host. Truncated unprocessed material stays pending, and the host warns the user in the foreground. Pi's compactions are this replacement, and so are Claude Code's manual and automatic main-session compactions when its function hooks are loaded (102); a plugin's, a precomputed or a subagent's compaction stays Claude Code's own. The replacement keeps no original message: the turn in flight (the prompt just submitted, or a tool call and its result) is the newest Raw in it.
- **Material window** — a compaction part: Knowledge has a database-derived 20k base and facts/Raw have configurable 10k bases (`compaction.factsTokens`, `compaction.rawTokens`). The shared allowance is one configured value (`compaction.sharedAllowanceTokens`, 10k by default), not derived from the triggers. Knowledge fills its base and borrows the allowance first; then Raw takes the newest contiguous span, pending entries borrowing what Knowledge left and already-noted entries only the Raw base; then facts take the newest not wholly covered by that span within their own base, without borrowing or consulting historical Consolidation progress. Each window is charged exactly what it emits, its receipts and framing included; a window with no room even for its receipt emits nothing. Bases never lend to one another. Knowledge bodies are optional current-version material. Fresh Noter and Dreamer Knowledge use the base plus shared allowance; Dreamer's pending slice is part of that window, not an additional window.
- **Refill** — superseded by the single allocation under Material window (73): already-processed Raw fills only its own base remainder after pending Raw; this refill is disabled only for Noting's exact pending batch. Facts fill their own window regardless of historical processing. A fact is excluded only when its nonempty complete source-entry binding is fully covered by the final Raw span or retained originals/recognized bounded carriers; this applies to unconsolidated facts too, which stay pending in the store. Complete bindings not wholly covered by Raw stay eligible; missing bindings or inconsistent stored segments are data corruption, not a coverage fallback. A discarded summary proves no retained coverage. Omitted items start no work, reset no processing and claim no supplied IDs.
- **Memory material coverage invariant** — withdrawn by 73: a compaction may truncate unprocessed Raw and unconsolidated facts, newest kept and oldest omitted with a receipt; the omitted material stays pending in the store for Noting and Consolidation, and the user is warned. An ID or omission receipt is not a body, and bounded Raw is not semantic losslessness.
- **Compaction boundary** — the last compaction the host successfully persisted on the selected ancestry. A request to compact, a failed or cancelled attempt and a compaction on a sibling path are not one. A Noter whose frozen entries include any entry before it runs with fresh context for the whole batch.
- **Trace** — address-directed reading: a Turn shows contributed fact segments and pending Raw; an entry or entry range shows Raw; a fact shows its segments and visible knowledge identities whose current or historical versions cite it; knowledge shows supporting fact IDs and titles. Exact tags (`K7#qfzt`), numbered history (`K7@v2`, `K7@v2..v4`), full-address comma lists and entry role filters remain supported. Block selectors, fact intervals, negation walks, `K7..`, `layer` and `tool` selectors are removed. Also the project name.
- **Search** — lexical lookup over facts and knowledge (and optionally a session's raw) returning addresses. No hit does not mean absent.
- **Memory files** — `/tm`, a read-only tree the model reads and greps directly: `/tm/<address>` renders exactly what `trace(<address>)` shows the reader on their own path (93); a write under it is refused. `/tm/knowledge` lists current visible knowledge; `/tm/knowledge-all` lists every knowledge identity in every scope and project, archives included, at its latest version — a legacy archive from before 99 (empty body, no kind) shows its parent's body there. `/tm/S<n>` and `/tm/S<n>/T<t>` list a session's Turns and a Turn's Raw entries. Grep over a directory searches every file under it in full: a Turn's complete Raw (never its compressed view), a fact's title and segments, and — under `/tm/knowledge-all` — every version's full text, marking each non-current version "(historical; latest v<n>[, archived])" and the current archive "(archived)"; a legacy archive's own empty body is not itself found there, only its creation version is. `/tm/S<n>/knowledge` is the inheritance view: the same injection selection run with an empty delivered set, so a subagent always reads its complete current foreground rather than a delta; deliberately not listed under `/tm/S<n>` (a recursive search would render every session's injection) and, like every `/tm` read, records no delivery and is not remembered. Every session's own delivered knowledge carries an injection notice line naming that S<n> and this path, letting a main agent hand a subagent one line to read its inherited knowledge from. The hosts answer `/tm` themselves: Claude Code's `tool.call` hook runs an exact lexical prefix check (`.`/`..` resolved, never touching disk) on Read/Grep/Glob and denies Edit/Write/NotebookEdit there; Pi registers same-name `read` and `grep` tools that serve `/tm` and delegate every other path to its own.
- **Global preference** — one of the defaults the Pi menu's Settings entry saves under `trace-memory` in the resolved agent settings file: Noter execution mode, N/D models and subagent thinking levels (Dreamer is always a fresh subagent), and the closed-session scope that decides whose finished sessions this executor may work on. They are the existing canonical configuration keys, not a second system; a project or environment layer still overrides them, and a saved value reaches tasks admitted afterwards while running tasks keep the mode, model, thinking level and scope frozen with them. Database Knowledge budgets appear in the same Settings screen but are not global preferences and never write that file.

## Process

- **Logical task** — one target session, phase and stable backlog key: the oldest selected source entry for Noting, the pool for Dreamer (whatever each run's range holds). An automatic failure can retry only at a later main turn end; manual catchup retains its immediate same-phase retry. Three terminal business failures of the same task disable memory; success resets that task and explicit on resets every target streak. Reopen does not reset it. Cancellation is not a business failure. Dreamer ranges end once; a catchup retry admits a new range without replaying committed changes. A Dreamer run succeeds only when its pool ends within its budget and every frozen version was operated on or skipped; a timeout or an over-budget end is a failure.
- **Disposition** — an operation or reasoned skip recorded by a model. Dreamer processing covers skips and own output, not the entire frozen range; a timeout is not a completed maintenance pass. Historical Consolidation skipped-fact reasons remain in its run audit.
- **NEAR** — historical Noter lexical-review audit only. New Noting has no similarity scan, feedback or mandatory relation review; old audit records remain readable.
- **Fork** — inherited-context execution: the run happens in a child of the conversation itself, continuing from its persisted state. The execution mode, never the evidence path called branch. Runs recorded before this name existed carry the old spelling and are read as legacy request-copy execution.
- **Subagent** — fresh-context execution: the run happens in a private child prepared from the frozen material alone. The alternative to fork.
- **Material** — the frozen parts one memory run works from: the active knowledge, the historical facts, the compressed Raw views of its selected entries, its own range and the budget receipts. A task freezes it once; both execution modes read that one.
- **Increment** — what an inherited-context run adds to a conversation that already carries the raw, the delivered facts and the injected knowledge: its instruction, the range, and the head reply and source index, or the exact fact list. Never a second copy of the material.
- **Run record** — an audit record for noting, consolidation, dreaming or manual work holding the exact input sent to the model, the prompt version, the model, the execution mode, and the output. Knowledge revisions point at the run that produced them.
- **Worker log** — the child session's own JSONL, written by the host itself, named in the run record as `nativeLog`. On Pi it is by default a direct child of the agent's `sessions/trace-memory` directory — one level under Pi's session root, where external daily-cost readers look, and where Pi's all-session browser lists it. On CC it is the worker's native Claude Code session, one directory under Claude Code's own `projects` root, named for `worker.cwd` — where claude-powerline's daily cost counts it like any other session. Neither host moves logs written under an earlier layout.
- **Completion level** — the prefix on an event fact: completed (result evidence visible), reported (claimed only), dispatched, attempted.
- **Writer schema** — foreground and Noter advertise identical note/memory schemas and descriptions. Runtime role checks reserve slot/drop and local knowledge supports for N; manual writes remain immediate, including their existing within-call relation handles. A Pi fork retains captured parent definitions and strict prefix verification; an incompatible old definition is explicitly refused through the existing fallback path.
- **Local handle** — `$n`, a stable fact slot in one Noter run; `Mn` identifies a held knowledge operation. Omitted slot appends; named slot completely replaces, including rejected values. Gaps remain after drop. Knowledge supports and optional earlier-slot fact relations resolve through an explicit slot-to-F map inside terminal publication, never by rewriting prose.
- **Commit durability** — the database trades some crash safety for a responsive event loop: an OS crash or power loss can roll back the most recently committed transactions (a few seconds of Raw, facts or knowledge); a process crash alone loses nothing already committed. Recovery needs no operator step: on restart, each host re-imports any Raw missing from the database out of its own native transcript or session, and Noting/Dreaming work whose commit was rolled back is pending again, exactly as if it had never run. A rolled-back run's spend record is lost with it.

## Languages

Memory content is written in the language of the conversation. Everything that is work — code, comments, docs, prompts, subagent briefs — is English.
