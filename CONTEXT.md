# Trace Memory — domain glossary

Terms only. No implementation detail. When a term here conflicts with usage in code or prompts, this file wins and the other side is fixed.

## Layers

- **Raw** — the conversation as the host recorded it: user messages, tool calls with results, assistant text. The only source of truth. Never edited.
- **Source entry** — one completed native conversation message: user text, assistant content with tool calls, or a tool result. Identity is its native id within the session lineage, never its text. It belongs to a Turn and receives an immutable Turn-local E ordinal; branch gaps never renumber it. The host normalizes ordered content blocks once for rendering and exact citation validation. Plugin injections and summaries are never sources.
- **Compressed Raw view** — the shared, bounded head/tail excerpt of one source entry, in Pi's compaction line shape with stable entry/block addresses (`[T<n>#E<m>@text] user: …`, `[T<n>#E<m>@<callId>] <tool>(<key>=<JSON>)`, `[T<n>#E<r>@<callId>] <tool> <status>: …`) and honest omission counts in one marker family (`[... N characters truncated]`). One view everywhere, under one profile of three independent budgets: `E` for the whole entry, `C` for each tool-call part, `R` for each tool-result part, each including the labels, syntax and markers inside it. A marked compressed view is visible Raw whether or not it was truncated. The original Raw remains available through full trace, uncompressed under the same labels, with lossless cursor pagination (default 2,000 estimated tokens per page).
- **Turn** — one user message and everything it triggered until the next user message. A compaction is also recorded as a turn, with no facts.
- **Fact** — one claim extracted from a turn that can be overturned on its own. Six categories: question, proposal, decision, observation, interpretation, event. Carries an actor (user or agent), a source address, optional verbatim quote, and relations.
- **Fact group** — the display of selected facts under their owning Turn: Turns in chronological start-time order, facts in ascending F-id order. A group need not cover its entire Turn; grouping changes neither citation scope nor processing membership, and all original source references stay on each fact.
- **Knowledge** — one durable, decontextualized conclusion consolidated from facts. Seven categories: constraint, open, dispute, goal, mechanism, term, reference. Each immutable revision stores the complete resulting body (or archival state) and exact lineage.
- **Supports** — the facts explicitly grounding one revision's change, not a copied complete-result evidence set. A new-format revision applies only where its own scope and direct supports and every exact parent's historical conditions apply. Effective grounding for trace, diagnostics and accounting is the recursive union; the stored list remains change-only. Legacy rows retain `complete_result` semantics rather than having a delta invented. Only a trusted Dreamer may submit an empty list for update/merge/split/archive; it inherits parent conditions and never means universal applicability.
- **Knowledge lineage** — creation has no parent; update/archive have one; merge has exactly two distinct parents and one result; split has one parent and atomically creates exactly two new Knowledge identities. A split relationship supersedes the parent only where the children apply, without manufacturing an archive. Both child histories and later descendants reach the original.
- **Trigger origin** — the target memory-session identity plus the immutable ordered `source_entries.id` sequence from selected native root through the exact triggering entry. Core copies it before work starts onto the execution, retained Dreamer range and runs; later branch-row mutation, same-Turn entries, foreground navigation and retries do not move it. Historical absence stays unknown. Within one target session, equal or prefix-related origins are one path and cannot create competing consumers of an exact base; non-prefix origins are siblings and may do so. Independent sessions keep the applicable-successor stale check.
- **Reason** — the commit message of one knowledge commit: what changed and why it was chosen. It is not a durable claim and has no authority of its own; it establishes no evidence, scope, applicability, accounting coverage or completion level, and addresses written in it are never read as citations.
- **Topic** — a subject label on one knowledge revision: the module, component or domain the conclusion is about, beside its category. Labels are free strings, trimmed, deduplicated and versioned with the revision that carries them; several may apply and none is required. Classification only — a topic changes no scope, evidence permission, lifecycle or eligibility, and sharing one merges no knowledge.
- **Noting** — the phase in which the Noter turns raw into facts. Each eligible entry completion checks for 10,000 pending compressed-view tokens; a run processes the oldest whole-entry prefix within 10,000 tokens and the model context capacity. A partly processed Turn may still have pending entries.
- **Dreaming** — bounded native-subagent update/binary-merge/binary-split/archive maintenance of a frozen knowledge family, with no parentless create, eligible when pending knowledge-change weight reaches 5,000 tokens or an unfinished retained range remains. It receives processed knowledge up to 20k, changed knowledge up to 10k and direct facts up to 10k; trace/search reads never enlarge its writable family. Legal memory batches commit immediately. Final acceptance derives candidates from formally supplied versions and this run's descendants, then certifies only successor-free leaves within shared processed caps: global 4k, project 10k, session 1k and applicable 15k, including framing. A consumed supplied base accounts for its own event without certifying, adopting or settling the consumer; all-consumed input may therefore complete successfully with no certificates. Settled events and exact-version certificates are separate shared facts. A currently applicable uncertified version restored by path navigation is a version obligation even when its old event was settled. One system-generated repair shares at most 50 tool rounds; its feedback is recorded as a host-generated user-role message, not evidence, and the same Dreamer system instructions remain on every continuation. Partial commits survive failure without certification. Neutral `conflict` remains only for an independently verified post-freeze successor of reference-only processed material that is the sole remaining acceptance blocker; it changes no failure streak. Retained event/version obligations, anchor and writable family stay immutable and are reselected as whole shared-result components within 10k; blocked components do not pin independent fitting retained work.
- **Consolidation** — the phase in which the Consolidator turns facts into knowledge and makes fact-backed single-identity create/update/archive changes. Similarity inspection and candidate review remain; automatic merge/split restructuring belongs to Dreamer. A same-path stale-base refusal is ordinary correctable feedback: the Consolidator may completely read the applicable successor, reconsider the same frozen facts and submit normally against that exact version; unresolved refusal remains a failure. Manual writes retain fact-backed binary merge, but gain neither split nor trusted empty-support maintenance. Each eligible entry completion checks for 5,000 rendered tokens of applicable unconsolidated committed facts, including facts of partly recorded Turns; a run takes the oldest-first whole-fact prefix within 10,000 rendered tokens. Worker completion, shutdown and tree switching launch neither phase; a compaction launches one bounded task of a phase only as **Compaction recovery** below.

## Relations (annotations, never derived state)

- **Support** — a newer fact affirms an older one: adoption, approval, agreement, an answer, a restatement, execution of a ruling.
- **Negate** — a newer fact opposes or invalidates an older one: withdrawal, veto, found wrong, a new state overturning the old, doubt, objection, evidence that does not fit.
- **Strength** — the Noter's confidence that the relation holds: *strong* when the raw states it, *weak* when inferred or partial. Who acted is carried by the fact's category and actor, not by the strength.
- No fact is ever hidden or retired by a relation. Relations show the Consolidator the shape; the Consolidator judges.
- **Dispute** — the Consolidator's judgment that two accounts of the same object under the same conditions coexist without a ruling. A category of knowledge, not a relation.

## Scope and attribution

- **Enrollment** — the durable enabled or disabled participation of one memory-session identity, changed by `/trace on` and `/trace off` (in Pi) for that identity alone, immediately and without a reload. Explicit intent overrides its derived default; shared forks and clones share the switch. Disable pauses future work and injection while retaining memory and unrestricted reads. There is no global participation switch.
- **Baseline** — the installation-scoped instant of the plugin's first successful initialization, retained across restarts and upgrades. Only native sessions created strictly after it default enabled; unknown or malformed creation times default disabled.
- **Session** — one host conversation. Gets an id only once an assistant reply exists.
- **Executor** — an enabled active host runtime that provides one Noting slot, one Consolidation slot and one Dreaming slot. The phases can overlap without a database-wide seat. A free slot prefers its own eligible work before borrowing a closed tail allowed by the configured Closed-session scope.
- **Closed-session scope** — the policy for automatically borrowing closed-session work: off leaves tails pending, project allows only the same project (default), and global allows any project. All three phases require an enabled, open executor session; scope does not change current-session processing or manual catchup.
- **Target** — the memory session and branch whose evidence a worker processes. Its project, costs, commits, progress and deliveries remain its own even when another executor hosts the worker.
- **Claim** — exclusive ownership of one target's phase across branches and executors, identified by an executor, a token and a thirty-minute expiry. Current ownership fences commits; reopening immediately replaces another executor's token.
- **Closed** — a session marked by normal shutdown and cleared on restore. A crash or expired claim does not establish closure; an unclosed crashed conversation waits for resume.
- **Project** — the unit that shares knowledge. Shared membership requires an explicit user command (`/trace project <name>` in Pi); the same name in the same database identifies the same project. Files, cwd and Git remotes do not declare membership. An undeclared session is its own project and may later be merged into another, retroactively. Existing stored project assignments survive removal of file-based discovery.
- **Scope** of a knowledge item — `session` (holds only in that session), `project`, or `global` (about the user, the environment, general working method).
- **Manual catchup** — `/trace catchup`'s finite, explicit drain of the current enabled session's selected branch: a frozen entry-id boundary for Noting and a frozen fact-id set for Consolidation, drained in bounded batches below the normal triggers, in subagent mode, chaining only within its own host-local controller. The sole exception to the no-completion-chaining rule; it never expands past what it froze.
- **Stop** — `/trace stop`'s cancellation of one executor's background work (its own manual catchup plus any ordinary or borrowed work), reusing the same claim, token-fence and cancellation machinery as shutdown. It never disables enrollment, never edits configuration and never touches another executor's claim.

## Reading

- **Foreground Knowledge delivery** — before every enabled ordinary prompt, the host may publish one Knowledge-only hidden message. The core selects applicable current exact revisions not already visible at that version, suppresses only changes whose nonempty direct supports are all visible as Facts or are all proven to bind to retained original/bounded Raw entries, and emits applicable archive/supersede/merge/split notices separately from bodies. The 20k Knowledge allowance charges retained applicable Knowledge bodies and state notices first; candidates then fit as whole rendered items. No Fact, Raw, omission-only, initial-only, command-generation, or processed-status material is published.
- **Injection** — the same Knowledge renderer and evidence-aware foreground predicate, used by every ordinary prompt; compaction separately carries knowledge, recent facts, and pending compressed Raw views. Knowledge is grouped by category in fixed order, and bytes change only when content or rendering changes.
- **Compaction** — replacement of the context with the injection block. Over a frozen snapshot of the path it has two outcomes: a custom replacement, or a request that the host's own native compaction take over. The core allocator calls no model. Host-managed bounded recovery may run model-backed memory tasks before either outcome; native delegation additionally uses the host's own summarizer.
- **Compaction recovery** — one bounded operation when required knowledge/facts/Raw excesses above fixed bases exceed their shared overflow allowance. At most one eligible Noting, Consolidation and Dreamer task, concurrent when independently useful; at most three rounds cover N→C→D eligibility dependencies. Each is one ordinary task, including Dreamer's internal repair, never a drain. Compatible exact-target/range reuse consumes the phase's use. Reallocation reads actual committed progress and exact processed versions, including after partial failure; final publication rechecks the coherent material snapshot and path/project binding. Still over with no eligible unused opportunity means native fallback. Third-failure automatic-off takes the native failure route, never an empty custom success. User cancellation cancels owned tasks or reused waits only and starts no native compaction.
- **Material window** — one of a custom compaction's knowledge, facts and Raw parts, with fixed base budgets of 20k/10k/10k. Required material is unprocessed exact knowledge versions with necessary status, unconsolidated facts and pending bounded Raw. Positive required excesses share a 10k overflow allowance; unused bases never lend. The derived maximum envelope is 50k. Processed supplements and their framing use only their own positive base remainder, never overflow. The Consolidator's 10k knowledge-reference allowance is separate.
- **Refill** — optional processed history in each compaction window's own base remainder: newest already-extracted Raw first, displayed in source order, then newest already-consolidated facts, displayed in chronological Turn groups. A fact is excluded only when its nonempty complete source-entry binding is fully covered by the final Raw set: retained originals/recognized bounded carriers, required pending Raw and selected history. Unknown, incomplete or partly uncovered bindings stay eligible; required facts are never excluded. A discarded summary proves no retained coverage. Filtering precedes budgeting; omitted items start no work, reset no processing and claim no supplied IDs.
- **Memory material coverage invariant** — a successful custom compaction preserves, for its selected path and material snapshot, every agreed Raw view awaiting Noting, complete fact awaiting Consolidation and current applicable knowledge version awaiting successful Dreamer maintenance. Completion transfers selected information to its next representation or deliberately retires it; successful maintenance may archive knowledge without an active replacement. An archive write alone does not complete maintenance: unfinished archive accounting/status remains protected. Optional processed material may be omitted; native compaction is the explicitly accepted lossy fallback. An ID or omission receipt is not a complete body, and bounded Raw is not semantic losslessness.
- **Compaction boundary** — the last compaction the host successfully persisted on the selected ancestry. A request to compact, a failed or cancelled attempt and a compaction on a sibling path are not one. A Noter whose frozen entries include any entry before it runs with fresh context for the whole batch.
- **Trace** — the tool that walks addresses: knowledge → its facts → the source turn; knowledge revisions (`K7@2`, `K7@2..4`); a fact's later strong negations (`F101..`). Also the project name.
- **Search** — lexical lookup over facts and knowledge (and optionally a session's raw) returning addresses. No hit does not mean absent.
- **Mark** — the user's verified / flagged / clear annotation on a knowledge revision, applied through `/trace mark K<n>[@<commit>] <kind>` (or the menu's Current session > Mark) and the façade. Project declaration is a separate user command.
- **Global preference** — one of the defaults the Pi menu's Settings entry saves under `trace-memory` in the resolved agent settings file: Noter and Consolidator execution modes, each phase's model and subagent thinking level (Dreamer is always a fresh subagent), and the closed-session scope that decides whose finished sessions this executor may work on. They are the existing canonical configuration keys, not a second system; a project or environment layer still overrides them, and a saved value reaches tasks admitted afterwards while running tasks keep the mode, model, thinking level and scope frozen with them.

## Process

- **Logical task** — one target session, phase and stable oldest selected backlog item: a source entry for Noting, the first fact in Consolidation selection order, or the original frozen change event/version obligation for Dreamer. Its identity survives retries, borrowed execution, growing tails and partial edits; a changing leaf or run id is not part of the key. Three terminal business failures disable the target's memory; successful completion resets that task, and explicit on resets every target streak. Reopening does not. Only Dreamer's independently verified reference-only external-successor conflict is neutral: it neither increments nor resets the streak, advances processing nor launches an immediate retry. Consumed formal input instead completes successfully; illegal operations and provider/validation/budget failures still count.
- **Accounting** — after each consolidation run, every user fact and every question in the range must be cited by a knowledge item or listed in `skipped` with a reason; missing accounting is a diagnostic.
- **NEAR** — the lexically nearest existing knowledge shown for every Consolidator candidate. Compare the actual claims and conditions before a single-identity correction or new admission; lexical similarity alone is not equivalence. Unanswered pairs remain diagnostic; merges and splits belong to Dreamer.
- **CLOSER** — new facts lexically near each open or goal knowledge, shown as candidate closing evidence.
- **Fork** — inherited-context execution: the run happens in a child of the conversation itself, continuing from its persisted state. The execution mode, never the evidence path called branch. Runs recorded before this name existed carry the old spelling and are read as legacy request-copy execution.
- **Subagent** — fresh-context execution: the run happens in a private child prepared from the frozen material alone. The alternative to fork.
- **Material** — the frozen parts one memory run works from: the active knowledge, the historical facts, the compressed Raw views of its selected entries, its own range and cues, and the budget receipts. A task freezes it once; both execution modes read that one.
- **Increment** — what an inherited-context run adds to a conversation that already carries the raw, the delivered facts and the injected knowledge: its instruction, the range, and the head reply and source index, or the exact fact list and review cues. Never a second copy of the material.
- **Run record** — an audit record for noting, consolidation, dreaming or manual work holding the exact input sent to the model, the prompt version, the model, the execution mode, and the output. Knowledge revisions point at the run that produced them.
- **Worker log** — the child session's own JSONL, written by Pi, named in the run record as `nativeLog`. By default it is a direct child of the agent's `sessions/trace-memory` directory — one level under Pi's session root, where external daily-cost readers look, and where Pi's all-session browser lists it. Logs written under an earlier default stay at their original paths.
- **Completion level** — the prefix on an event fact: completed (result evidence visible), reported (claimed only), dispatched, attempted.
- **Local handle** — `$n`, the n-th fact of the current noting batch, used for in-batch relations before ids exist; the writer resolves it.

## Languages

Memory content is written in the language of the conversation. Everything that is work — code, comments, docs, prompts, subagent briefs — is English.
