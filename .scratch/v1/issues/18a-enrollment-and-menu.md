# 18a — Session enrollment, mode-independent delivery, read-only settings, menu

**Parent:** 18 — Session enrollment and settings menu (rulings and full decisions live there; the sections "Manual catchup and stop" and the catchup/stop parts of the menu belong to 18b).

**What to build:** one persistent enrollment state per Trace Memory session, enabled or disabled, with explicit choices stored apart from derived defaults. A native Pi session whose header timestamp is strictly after the installation baseline (one durable timestamp written atomically at the plugin's first successful initialization) defaults to enabled; earlier, equal, missing or malformed timestamps default to disabled; an explicit choice always wins and survives reopen, upgrade and tree navigation; a fork or clone carrying an existing memory identity inherits that identity's state. Enrollment resolves before the first reply through a provisional choice on the host state that transfers when the memory session is allocated. Enabled sessions ingest sources (17a's attach-time reconciliation imports the current path when enabling, no model call), receive the session-start knowledge block and both delivery kinds regardless of worker mode (the configuration-derived delivery switches from commit 2ff66be are deleted; the branch-mode wait for a pending delivery stays), run automatic Recording and Integration under 17b, and accept manual writes. Disabled sessions ingest nothing, inject nothing, run nothing, reject `note` and `memory` with an enable instruction, keep `trace`, `search` and status, keep their stored facts, knowledge and runs, and are not catch-up targets (17c, later). Disabling persists first, rejects new admissions, and the commit path re-reads enrollment so an in-flight run that finishes after disable writes nothing; cancellation of in-flight model calls is 17c's, not this slice's. Re-enabling reconciles the paused interval from native history. Configuration is read from the `trace-memory` key of Pi's global and project `settings.json` with `TRACE_MEMORY_CONFIG` on top, reusing the existing retry-settings reader; nothing writes configuration. `/trace` with no arguments opens a native menu (Current session with enable/disable and the default-or-explicit origin, Settings read-only with each value's source, Runs, Status); `/trace enable`, `/trace disable`, `/trace status` and the existing forms stay; headless bare `/trace` prints status. The footer distinguishes Disabled from idle.

**Blocked by:** 17b (landed as 9b4bb44). Not blocked by 17c.

**Status:** ready-for-agent

- [ ] A native session created before the baseline is disabled by default, one created after is enabled; equal, missing and malformed timestamps are disabled; a concurrent or repeated first initialization keeps one baseline; reopening an old session does not make it new.
- [ ] Enable an old session and disable a new one; both choices survive reopen, tree switch and configuration reload; a fork sharing the memory identity inherits the state and the menu says so.
- [ ] Toggle before the first reply; the choice transfers to the allocated memory session without an artificial Turn or a duplicate session.
- [ ] Enabling a conversation with several pre-plugin Turns imports them through 17a reconciliation with stable addresses and one entry each; the import makes no provider call; the next eligible completion schedules only what 17b allows.
- [ ] Disabled: no ingestion, injection, extraction or delivery confirmation; `note`/`memory` are rejected with the enable instruction; `trace`/`search`/status work; a run that commits after disable is rejected at commit and its batch stays pending; a commit that won before disable stays.
- [ ] Enabled sessions receive `<recorded>` and `<integrated>` deliveries in all four Recording/Integration mode combinations; the mode-derived gating is gone.
- [ ] Configuration layers global file, project file and environment in that precedence; invalid values fail loading by key; the menu shows each effective value and its source; nothing is written.
- [ ] Menu and commands produce the same state; cancel changes nothing; headless bare `/trace` prints status; the footer shows Disabled.
- [ ] Revert probes: default by first-seen time instead of the native header, only the menu checking enrollment, fork restoration overwriting the current switch, and delivery gated on worker mode again each make a named test fail.
