# 20c — Compaction escalation, post-compaction worker mode, catchup batching

**Parent:** 20 — Shared memory material and bounded compaction (sections "Compaction escalation", "Post-compaction worker mode", "Catchup and stop continuity"; acceptance scenarios 9–14, 16, and the native check in Testing Decisions).

**What to build:** compact escalates in three deterministic tiers over a frozen read snapshot of every pending entry on the current path (reconciled, no extraction trigger, no progress change). Tier 1: all pending primary views within the Raw ceiling and the episodic framing within its budget. Tier 2: a versioned, deterministic, explicitly labelled compact-only secondary view of all selected entries — tool fragments keep name and the minimum source identity for trace, drop arguments and results; user and assistant text get bounded excerpts with omission markers; order, user boundaries and non-text placeholders preserved — rechecked under the same accounting. Tier 3: an explicit core result asking for native compaction with a reason; the Pi host returns no custom replacement and lets Pi's own compaction (which may call a model, fail or be cancelled) run and report normally. No tier waits for, cancels or launches a Noter; a concurrent commit survives; summaries never become sources, facts or progress; the used tier and reason are visible in diagnostics. After a successfully persisted native compaction on the target's selected ancestry (custom or Pi summary; not a request, a failed or cancelled attempt, or a sibling path), a Noter not yet in native execution whose frozen entries include any pre-boundary entry runs as subagent for the whole batch with a recorded pre-compaction-evidence reason, rechecked at launch; a running fork finishes against its frozen context; post-only batches use the normal mode; enrollment, configuration and cache suppression are untouched. Manual catchup drains successive bounded Noting batches, then successive bounded Consolidation batches until its frozen target is exhausted (superseding 18b's single Consolidation call); stop discards only the invocation's remaining plan.

**User confirmations (2026-09-08):** the secondary-view excerpt lengths are an implementation choice — one versioned, documented constant set, not a user ruling; tier 3 is the one place where compaction may reach a model call, and only through Pi's native path.

**Blocked by:** 20b — Hard material budgets (the compact tiers are measured against the shared caps).
