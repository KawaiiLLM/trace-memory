# 16a — Knowledge commits: immutable commits with parents, path-computed current, evidence-based applicability, base-commit concurrency

**What to build:** The store and the tool layer implement the spec section "Knowledge commits and paths" (user rulings 2026-09-07). `knowledge` keeps the stable identity; `knowledge_revisions` rows are the commits, addressed by their global id (`K1@57`), each with a parent commit (merge: several, through the links table), text, category, scope, supports, because and run. `current_revision` and `status` are deleted; the current commit of an identity is computed per path. Applicability is decided by evidence: a commit applies on a path when every fact it cites from its own session lies on that path (other sessions' facts do not restrict; scope decides which sessions see it). Writes cite only facts allowed by the scope table; a batch names the base commit of every update, merge and archive and is rejected whole when that base has an applicable successor on the writer's path.

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

Rulings, verbatim: 「前缀用K。…其他分支的对话是可见的…但其他分支不能supports本分支的知识，其他项目/会话能否supports本会话知识取决于知识的scope」; A: 「根据当前根节点到目前节点的路径计算即可，看覆盖事实能退出的最新版本」 (applicability by the facts a commit cites, along the root-to-node path); B: 「可以」 to the base-commit check with no shared-head registry, cross-session linearity, branch divergence, tips surfaced never last-writer-wins.

- [ ] Schema: `knowledge_revisions.parent_id` (nullable, REFERENCES knowledge_revisions); the per-identity `rev` column is removed and every address uses the commit id; `knowledge.current_revision` and `knowledge.status` removed; merge parents recorded in `knowledge_links` (`merged_into` from each absorbed commit to the merge commit); archive is a commit with empty text and `op = 'archive'`; no migration code (v1 unreleased)
- [ ] Store: `currentCommit(knowledgeId, path)` and `listCurrentKnowledge(path, scope filter)` where a path is a session id plus head turn id (root-to-head ancestor chain), or "no path" for context-free callers; a commit applies when all cited facts of its own session are on the path and its scope admits the session; current = applicable with no applicable successor; several tips are returned as a list, never collapsed
- [ ] Tool layer `memory`: `id` of update/merge/archive names an identity; the base commit is the path current at read; on submit, any base with an applicable successor on the writer's path rejects the whole batch with the current commit named; supports and because must satisfy the scope table (session: own path; project: own path plus same-project sessions; global: any session); citing a sibling branch's fact is rejected with "record an adoption fact on this path first"
- [ ] Injection, compaction, Integration context, NEAR and accounting use the path current set; a context-free read (façade without session) uses the tip list
- [ ] Marks bind to commits: `mark(commitId, kind)`; the façade resolves a bare `K<n>` to the caller's path current and rejects a write when several tips exist
- [ ] Ruling tests named after A and B: the C/D example (C sees @c2, D sees @c3, the fork ancestor sees @c1, D's later commit does not move C), the revert-then-develop chain on one path, a pre-fork-evidence commit applying to both branches and forcing the sibling's later base check to fail, cross-session concurrent edits rejected linearly, an archive effective only on its path, a sibling-branch citation rejected, two tips surfaced to a third session
- [ ] Existing tests and goldens follow the new addresses; report the production line delta and every query that changed
