# 23a — The entry renderer, its two budgets and two profiles

**Parent:** 23 — One entry view, two budgets (everything except the `trace` assembly rule and the deletion of the explicit Turn preview's per-tool branches, which are 23b). The parent's "Implementation Decisions" are binding here verbatim: the rule, the budget contract, the profiles, the host contract, the settings changes for the keys named below, the rulings touched.

**What to build:** `renderEntry` renders every source entry by the parent's rule under a profile `{B, E}`: parts (at most one natural-text part, one part per tool call), tool-call parts as label plus one `key: value` line per argument with fair-share head cuts, tool-result parts as label plus host-extracted text cut head and tail with an omission marker (structured data dropped by the host marked with its size, or rendered as its compact-JSON head when the text is empty), images and other non-text blocks marked, no call id and no native-identity header in the text; allocation with `B` caps first, then tool parts giving way to the label-plus-marker minimum, then text; the budget contract verified before returning; the existing capacity error when minima exceed `E`. Two profiles: tier 1 `B = 300, E = 10,000` (Noting material, compaction tier 1, branch carry) and tier 2 `B = 100, E = 150` (compaction tier 2). The compaction-only secondary renderer and its version constant are deleted; tier 2 calls the one renderer with the tier-2 profile. The host registers a result-text extractor with the façade at construction (default: the stored string as is); the Pi host's extractor joins text blocks, marks non-text blocks and reports `details` as dropped structured data with its serialized size; evidence storage is unchanged. Settings: `toolCallTokens` default 300 with a hard ceiling of 1,000 (rejected above), `entryTokens` unchanged, the tier-2 pair added under the same namespace (defaults 100 and 150), and `stdoutHeadTokens`, `stdoutTailTokens`, `stderrTailTokens` moved to the removed-settings table (never effective on Pi). `commandTokens`, `reportHeadTokens`, `reportTailTokens` stay until 23b, because the explicit Turn preview still reads them. The entry view version constant changes; run audits record the version and both numbers of the profile used; the compaction custom entry names the new version and profile. The Noter prompt sentence describing entry labels is updated to the addresses shown; the prompt hash moves; the fork gate is re-run against the updated parent request, never assumed.

**Explicit `trace` in this slice:** the explicit Turn preview keeps its current output byte for byte (23b changes it after 22c lands), so this slice must not touch `renderTurn` or the `trace` code path. Noting material, compaction tiers and branch carry switch to the new renderer.

**Parallel execution:** this slice runs in its own git worktree on branch `ticket-23a` while 22c works on `trace`/`search` in the main tree. Commit on that branch (this is the one slice where committing is the handoff); the acceptor merges after 22c lands.

**Blocked by:** None for the renderer, profiles, host extractor, settings, prompt and compaction changes (they do not touch `trace`); the merge into main waits for 22c.
